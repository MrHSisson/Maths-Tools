# Decks — whole lessons, and the slide editor

**Read when:** Building or changing a deck, a slide layout, a deck element, a slide-owned question set, the player or the editor. For the shape and house style of a whole deck, also read `docs/design/LESSON_STYLE.md`.

A **deck** is one combined, directed lesson for the projector, played at `/decks/<id>`. It is also a small slide editor, a stripped-down PowerPoint around the site's own pieces: a teacher can refine a deck Claude built, add slides to it, or build their own. Decks wrap what the site already has (generators, authored question sets, boards), so a lesson stays in one place; tool pages are unchanged. Decks are the intended successor to the per-tool Teach deck and Lessons modes. Plan: `docs/pathways/decks.md`.

## Pages

| Address | What |
|---|---|
| `/decks` | The deck editor's list: every deck (built, edited on this device, and the teacher's own), **New deck**, the Slide library link, and a "published" mark. **Needs the admin password** |
| `/decks/library` | Every slide layout with sample content, grouped by family, plus the planned pieces. **Needs the admin password** |
| `/decks/<id>` | The player. Anyone sees the **published** copy, read-only (no Edit). With the password it shows the working copy, with **Edit** (`?edit=1`, password needed) and **Present** returning; `?published=1` shows the published copy to an admin |

**On a phone a deck is only previewed** (`usePhoneDevice`, `src/shared/layoutMode.ts`: a touch screen whose shorter side is at most 600px, so a phone held sideways counts and a narrowed laptop window does not; **View as** overrides it). `/decks`, `/decks/library` and `?edit=1` go to the Decks page or the player, the Decks page has no **Deck editor** button, the player has no **Edit**, and the tool pages' **Send to a deck** and **Edit in a deck** are not offered. The player opens on a start card; the tap is what lets the browser go full screen and ask for landscape (`screen.orientation.lock`, which only some Android browsers allow). Where it is refused, an upright phone shows the whole show turned a quarter turn clockwise (a box as wide as the screen is tall), so turning the phone sideways reads it upright; held sideways it is drawn normally. A swipe from right to left goes forward (it takes the next click on a slide before the next slide, as the keys do) and left to right goes back (`swipe.ts`, `swipeOf`: quick, at least 50px and mostly along the slide's width; in the turned show the same swipe is up or down the glass). The controls bar shows as the show opens and fades after four seconds; a tap on the slide shows it, and a tap while it shows hides it at once (a tap on a button or anything else on the slide that takes a tap is left to that; a swipe never touches the bar). Ink is off on a phone's deck and the controls bar stays centred, with no drag grip. <!-- ref -->

Reached from the **Decks page** (`/deck-gallery`, reached from the "Decks" button in the landing page header): the published decks as cards (the first slide as a preview, kept in the published listing so the tab loads no decks), and a **Deck editor** button that asks for the password. The tool's burger menu also lists "Deck: <title>" in Developing-tools mode (`decksForPath`).

## Published decks (`published.ts`, `AdminGate.tsx`, `api/decks.ts`)

- **Publishing** is a button in the editor's File menu (**Publish this deck**, **Publish again**, **Unpublish**; `npm run deck -- publish <id>` does the same from the command line). It sends a frozen copy of the deck, with its questions embedded, to the `maths.published_decks` table (the frozen copy and its listing entry together; the two public GETs are cached for a minute); the working copy is untouched and later edits change only the working copy until it is published again.
- **Reading is open to everyone** (`GET /api/decks?published` and `?published=<id>`); everything else on `/api/decks` still needs the admin key. The Decks page and the read-only player read only the published copies, never the working copy or this device's saved edits. <!-- ref -->
- **The password** is the Developing-tools password and the same switch: entering it at the editor's prompt turns Developing-tools mode on, and turning that off locks the editor again. It is a light check, not security: the string is in the site's code (`src/devAccess.ts`).
- Published decks come from the website, so the local dev server and an offline device show "can't be listed here". `npm run smoke:published` checks the whole flow with the service simulated. <!-- ref -->

## The model (`src/decks/types.ts`)

- A **deck** is `{ id, title, summary, tool?, toolPath?, slides }`.
- A **slide** is `{ id, family, title, brief?, els }` (`brief` is the optional slide brief; older decks' `intent` / `questionBrief` are folded into it by `withBriefs` when the editor opens a deck): a canvas `CANVAS_W × CANVAS_H` (1600 × 900) units, scaled to fit. The family sets its accent bar (`FAMILY_STYLE`; none is green, yellow or red, the level colours); the title names it in the jump list and the slide strip.
- An **element** is a box (`id, x, y, w, h` in canvas units; a line runs from `(x, y)` to `(x + w, y + h)`, so its `w`/`h` may be negative) and one of:

| `kind` | What | Notes |
|---|---|---|
| `text` | Text, `$…$` inline maths, a new line per line | `size` (≥ `MIN_TEXT` = 26), `bold`, `colour`, `align`, `middle` |
| `shape` | Rectangle or ellipse | `fill`, `stroke`, `strokeWidth`, `radius` |
| `line` | Line or arrow | `colour`, `width`, `arrow` |
| `image` | A picture, stored as a data URL | Large images are scaled to the canvas and saved as JPEG on upload |
| `maths` | An equation on its own | `latex`, `size`, `colour`, `align`; made and changed in the equation editor |
| `ratioTable` | The site's ratio table (`RatioTable`): quantities as columns, a row per scale step, the factor between two rows as an arrow outside the table | `table` (`headers`, `rows`, `operations`: one LaTeX factor such as `\times 2` between each pair of rows, `given`), `fill` as a board (Structure only keeps the headings and the given rows and hides the arrows; empty cells draw as "?"), `size` (cell text size), `staged` (one more row, with its arrow, per click). The table is laid out at its **full size** from the first click, with later rows hidden in place (`hideFrom`), and fitted to its box once from the whole table, so a four- or five-step table never rescales or moves as a row arrives | <!-- ref -->
| `numberGrid` | The 1 to 100 grid (`NumberGrid.tsx`, logic in `src/shared/numberGrid.ts`): **Structure only** (default) is the plain numbers, tapped to scribble in the chosen prime's colour (2 blue, 3 green, 5 orange, 7 purple; the prime circled) with **Finish the n times table** completing the rest while keeping tapped marks; **Filled in** is the finished sieve; **Blank** an empty grid. Marks are hand-drawn scribbles seeded by the number, not coloured cells. Taps are live in the player and are not saved. | optional `fill`, `staged` (one click per sieve step: 1 crossed out, then each prime in `stages`, default 2, 3, 5, 7), `stages`. The player's top bar has **Print grids** (the `hundredSquareSheet()` printable, two 1 to 100 grids per A4) on any slide that has one |
| `ink` | Hand-writing on a slide, drawn with the editor's **Pen**: one full-slide layer per slide (`x 0, y 0`, the whole canvas), strokes `{c, w, p}` (colour, width in slide units, flat points) in slide units, drawn smoothed by `InkLayer.tsx`. Not selectable on the slide; **palm rejection**: with the Pen on, a touch that is large (over 32px) or lands within 0.8 s of the stylus touching or hovering is swallowed by the editor's stage (`isPalm` in `Editor.tsx`), and no touch reaches the box-select or deselect underneath (the Pen toolbar has **Rub out** (whole lines you touch, `inkMath.ts`), **Clear** and **Done**; Esc stops); undo works as for any edit; it merges like any element and shows in the player, thumbnails and exports | `strokes` |
| `bar` | The site's bar model (`BarModel`, `src/shared/barModel.ts`) in two looks: the **ratio look** (`rows`, the stacked layout Ratio Sharing uses: a row per quantity aligned from the left, white boxes with a navy border, a value in each box, "= total" at the end, purple extra boxes for a difference, a brace across the rows) and a **single bar** of coloured parts with braces above or below (for fractions) | `bar` (`rows`: name, units, `unitLabel`, `total`, `extraFrom`, `known`; `sideBrace`; or `parts`: units and tone; `braces`: from, to, label, below; `unitLabel`), `fill` (Structure only: the coloured boxes without braces or labels; Blank: empty boxes), `size`, `staged` (rows: one row per click, then the brace, then every value and total together; single bar: one part per click, then one brace per click; the layout is fixed from the whole bar so nothing moves) |
| `board` | A table to write on | `grid` (`head`, `rows`, `given`), `fill` (Filled in / Structure only / Blank: a control in the player bar; B cycles modes), `size` |
| `questions` | A curated sequence of deck-owned questions | `items: CuratedQuestion[]`, optional `size`, shared `presentation` and `visualiser`; open response, multiple choice, compare claims, find the first error |
| `practice` | Legacy bank references | Read for compatibility; converted to deck copies when editing/exporting. Generator fallback is no longer used. |
| `grid` | Several open-response questions at once | Embedded `items`, `cols`, `size`; the answer replaces the question in its box (all at once with Show answers or `a`, or one box with a double-tap); legacy `bank` references remain readable. Rich diagnostics belong in a Questions activity. |
| `generator` | The tool's generator live, like its Whiteboard | `tool`, `preset` (`sub`, `level`, the tool's Question Options), `seed` (the first question, the same every time), `prompt` (blank: the tool's instruction); New question, the shared solution stepper, the answer (keys `n`, `s`, `a`); shared `presentation` (`full`, `whiteboard`, `whiteboard-inverted`) and optional `visualiser` select the saved display layout |
| `worksheet` | A book activity: `count` generated questions, numbered | `tool`, `preset`, `count`, `cols`, `seed`; answers on demand (shown in place of each question, like the worksheet), a **double-tap** on a cell flips just that cell, a small regenerate button on each cell (hidden until the activity is pressed, then it fades after a few seconds) replaces that one question with a new one that is not already on the slide, and New set (no Print button); `size` defaults to 60. A worded question shows its maths line at full size, and an instruction shared by every question is shown once above the set |
| `depth` | One of a tool's Depth items, drawn by `DepthSlide` (`src/shared/components/DepthSlide.tsx`), **the one Depth design: the tool page's Depth section draws the same slide** | `tool`, `item` (an id in the tool's `__test.depthItems`); a reference, not a copy, so editing the bank changes every deck that uses it. Show answer turns it to the answer in place; Change card… picks another. Older decks that hold a Depth card as a copied one-question set are turned back into references when read (`normalise.ts`) |

Any element may carry `step` (1, 2, …): it appears on that click when presenting (Next reveals a slide's next click before moving on; Back hides it). The split discussion layout uses it for its fixed order: prompt, key point, question, answer. The ratio table and bar model share the board's Filled in / Structure only / Blank control in the player bar (B cycles). Still to come: the other core representations (place value table, number line, area model, algebra tiles, counters, prime factor tiles), a timer, match-up and sort (listed as "Planned" in the library). Generator slides draw a ratio-table or fraction-bar working step as its picture (the bar scaled to fit its panel, a long worded question set smaller so it fits); fixed questions cannot hold one yet.

## Worksheets pinned to a lesson (`worksheets.ts`, `WorksheetsDialog.tsx`)

A lesson can pin up to three printable worksheets (`MAX_PINNED`). A pinned worksheet is an ordinary book-activity element (`kind: "worksheet"`) with `pin` set (`title`, `paper` A5 or A4, `layout` grid or list, `borders`, `fontPx`), so saving, sharing, undo, copy and export need nothing new. It prints through the same layout engine as the tool pages' Worksheet (`handlePrint`, `src/shared/print.ts`) on an **A5 page** by default: questions, an **answer sheet** (the same boxes in the same places as the question sheet, each with only its answer in it, set larger: `answerScale`), or both. A5 pages print two to an A4 sheet with "Pages per sheet: 2" in the print window. `frozen` keeps the generated questions (working left out, with a `sig` of tool, setup, count and seed) with the deck, so a printed sheet and its answers do not change if a generator does; it applies only while the setup matches, and otherwise the same seed regenerates the same set. <!-- ref -->

- **Pin it:** tick *Pin to the lesson* on a book activity (properties panel: title, page, layout, borders, text size, **New set**, **Print**, **Answer sheet**), or Add slide → **Worksheet**, which starts a pinned slide and opens the generator setup.
- **Print it:** File → **Worksheets…** lists the pinned sheets with Print, Answer sheet and Both.
- **Getting to them:** a **Worksheets** button sits in the top bar of both the player and the editor (shown only when the lesson has pinned sheets) and opens the same window as File → Worksheets…; on a worksheet slide the player's bottom bar also has **Print sheet** and **Answer sheet** buttons.
- **On the slide:** a pinned worksheet can show **the answers** (`view: "key"`, the Worksheet layout's default): numbered answers hidden until `a`, the cue to hand the sheet out. Showing the questions (`view` absent) draws the book activity, without its New set button so the slide always matches the paper. <!-- ref -->
- A hand-written sheet is a pinned worksheet whose `frozen` set is written by hand (worded questions, `working: []`, `sig` copied from the sheet's tool, preset, count and seed): it prints and shows its answers exactly as written, until the seed or setup is changed (then the generator takes over). `specs/decks/_check/ratio-w3-build.py` is the pattern. A worksheet carries no scaffold; the questions fill the page and pupils answer in their books.

## Rectilinear diagrams and authored worksheets

The generator picker includes **Perimeter & Area → Rectilinear Shapes** (its stable sub-tool id remains `compound`). Live slides retain the tool's `Drawing` and per-step focus, use the shared `ShapeDiagram`, and keep found lengths visible while advancing the solution. A stable seed chooses the first question; New question resets working and answers. Send to a deck honours the same sub-tool limit; diagram questions offer generator/whiteboard/book activities, while fixed chosen dimensions are authored in Skill practice. Other picture tools remain excluded. Full-width and workspace layouts both display the shape. Board length labels are enlarged independently of the unchanged worksheet labels; rectilinear levels default to reduced labelling. <!-- ref -->

In Skill practice, **Add rectilinear shape** creates a portable dimension-based question. Its controls choose L, T or a three-step staircase, overall dimensions and cut-out sizes (whole centimetres), rotation/reflection, split-and-add or whole-minus-cut-outs, reduced labelling and support. L-shapes can mark one missing length for addition or subtraction; the working finds it before area, and helper labels do not give it away. T-shapes use equal side cut-outs; staircases use two equal steps and a remaining step. Invalid dimensions disable Apply; dimensions, diagram, answer and canonical working update together. `api/_rectilinear.ts` validates the versioned specification; `src/decks/rectilinear.ts` builds through the live tool's `buildCompound` and independently checks area from the dimensions. `Q.rectilinear(id, spec)` is the script authoring entry point. No picture is serialized as HTML. <!-- ref -->

A completed shape set offers **Make printable worksheet** while fewer than three worksheets are pinned. This saves the practice draft and inserts an independent authored copy on a new worksheet slide. Double-click that worksheet (or Configure) to edit its fixed questions. Each question chooses **Split shown and calculation prompts**, **Split shown, working space**, or **Independent, working space**. Supplied splits label internal component dimensions that have no directly aligned boundary label. The `authored` questions remain fixed when other generator settings change; they are validated on save and preserved by copy/export/import. <!-- ref -->

File → Worksheets prints the questions, worked answers, or both. Authored shape sheets default to A4, six questions per page (A5 uses two), with SVG diagrams and writing space. The printed answer pages match the question order and include the method. Generated rectilinear worksheets also print their diagrams. Older generated/frozen worksheets retain their existing path. `diagramPracticeSheet` in `shared/printables.ts` supplies the shared page layout. <!-- ref -->

Verification: `npm run smoke:rectilinear-deck` uses `SMOKE_URL`, `PLAYWRIGHT_PATH` and `CHROMIUM_PATH` like the other deck checks. It isolates all deck API calls from live data and checks invalid edits, save/reload, worksheet creation, diagram reveal, phone/tablet/laptop presentation and printing through the Worksheets dialog. Unit coverage lives in `rectilinearDeck.test.ts`.

## Layouts (`src/decks/layouts.ts`)

A layout is a function that returns a pre-arranged slide of ordinary elements: title, learning objective, section divider, summary, key vocabulary, key definition, two columns, board, skill practice, quickfire block, Depth card, split discussion, retrieval starter, exit ticket, blank. Families: Lesson (structure), Language, Teach, Practice, Depth, Discussion, Retrieval. `LAYOUTS` lists each with its sample content and when to use it; the editor's **Add slide** and the library both read it, and the built decks are written with the same functions (so a built deck and a teacher's slide are the same kind of thing). Add a layout only when a lesson needs it, after checking none in the family does the job.

## Built decks, edits and the teacher's own decks (`src/decks/store.ts`)

- **Decks are data** (the shared copy; `src/decks/data/<id>.json` is its backup in the repo; the deck holds its own `tool` and `toolPath`). The shared copy (cloud) is the master, because Harry edits there: Claude runs `npm run deck -- pull <id>` first, changes the JSON by slide id, then `npm run deck -- push <id>` (`npm run deck -- list` shows what is shared). Push only a deck you have just pulled. **Decks are not bundled into the app (since 2026-11-11):** a device lists only the decks it has synced from the shared copy (the Decks page, the editor list, a tool's menu and the dashboard each sync on opening), so a brand-new device offline shows none. The repo JSON is a backup and what the tests (`src/tests/snapshotDecks.ts`) and `npm run deck` scripts read. Deleting a deck in the editor deletes the shared copy and this device's copy (there is no "Reset to the original" any more); a repo snapshot of a deleted deck is removed by hand. Slide ids are stable (`<deck>-<slug>`). <!-- ref -->
- **Edits are saved on this device** (localStorage) as the teacher makes them: an edited built deck is saved whole under `mt-deck:<id>` and **Reset** returns it to the original; a teacher's own deck (`my-…`) is listed in `mt-decks-mine`. Question copies are embedded in each deck. Editing them changes that deck only and participates in deck undo. `mt-deck-bank` retains old personal library records for legacy reference resolution. Ordinary authoring has no library browse or save action. <!-- ref -->
- **Export** materializes legacy question references and downloads the complete question content, including misconception descriptions and teaching guidance, as JSON; **Import slides** appends a file's slides to the open deck. Copy / paste (Ctrl+C / Ctrl+V, or the slide's Copy button and "Paste a copied slide") works between slides and between decks.
- **Shared between devices** (`src/decks/cloud.ts`, `api/decks.ts`, `api/_decks.ts`): every save is sent in the background (a moment after the last change) to `/api/decks`, which keeps the decks in **Neon Postgres** (since 2026-11-11; schema `maths`, created on first use by `api/_db.ts`; every read and write is in `api/_deckStore.ts`): `decks` (the deck as JSON, its summary columns for the index, and a `version`), `deck_versions`, `published_decks` and `questions`. A save reads the deck with its version, merges, and writes only if the version has not moved (retried if another save got in first); the list of decks is a query on the summary columns. The connection is `DATABASE_URL` (the Neon integration on the `maths-tools` project; the one database serves Production, Preview and Development, so a Preview deployment writes real data). Decks used to be Vercel Blob files (`decks/<id>.json`, `decks-index.json`, `history/`, `published/`, `deck-questions.json`); `api/migrate-decks.ts` copied them across once (temporary, safe to re-run) and is deleted once the move is confirmed. Opening the deck list or a deck pulls any copy newer than the device's (`syncFromCloud`, comparing the deck's own `updatedAt`); nothing is pulled while editing. **The first open of a deck waits for the shared copy** ("Loading the latest copy…", at most `LIVE_WAIT_MS` = 4 s, then the device's copy is used), so an older copy is not shown and then swapped; this also covers opening straight into `?edit=1`, and the deck list (`/decks`) waits the same way ("Loading the latest decks…") before drawing its cards. Header `x-admin-key` as for `/api/tool-notes`. **Shared version history** (the rollback for the live copy): before a save changes the stored deck, the service keeps the deck as it stood in `deck_versions`, at most one every `SNAPSHOT_GAP_MS` (10 min, so a spell of typing makes one) and the latest `MAX_SNAPSHOTS` (40); a save that changes nothing makes none. `GET /api/decks?history=<id>` lists them (newest first) and `&key=<key>` returns one; File → **Version history** shows them above the device's own, and Restore applies the old copy as an ordinary save (so it merges like any save, and Undo reverses it). A failed snapshot does not fail the save. Deleting a deck does not make a snapshot, and its earlier snapshots are kept. Tests: `decksHistory.test.ts`. A deck over 4 MB (large pictures) is refused with a message. Where the service is not reachable (the local dev server, no connection) the decks keep working on the device and the status line says so.

## Building a deck quickly (`builder.ts`, `deckChecks.ts`, `npm run deck`)

A new deck is a short script, kept outside the repo (the scratchpad), that default-exports a function returning the deck. `S` makes slides (title, board, deliberate practice, general practice generator, book activity, quick grid, Depth card, discussion…) and `Q` makes questions with the tool's own working (`Q.rounding`, `Q.estimate`, `Q.fraction`, `Q.open`); each `Q` builder writes the working the tool does, so only the numbers are typed.

```ts
import { Q, S } from "/src/decks/builder";
export default () => ({ id: "my-deck", title: "My deck", summary: "…", tool: "estimation", slides: [
  S.title("m-title", "My deck", "Round first"),
  S.deliberate("m-set", "Estimate products", [["42", "18"], ["63", "29"]].map(([a, b], i) => Q.estimate(`m-${i + 1}`, "level1", a, "\\times", b)), "Brief."),
  S.general("m-gen", "Whiteboards", "estimation", { sub: "estimation", level: "level1" }, 3),
] });
```

Fixed questions that carry a tool's own working: `Q.ratioSimplify(id, level, parts, ask?, method?)` and `Q.ratioFraction(id, level, spec)` make a question with the Ratio Manipulation generator's code (fixed numbers, wording chosen with `variant`) and check its answer from the parts; `fromWorked` (`questions.ts`) turns any generated question into a fixed one. A working step that is a picture (a ratio table growing a row per step, the fraction bar model) is kept as a line `caption` + newline + `@ratiotable {json}` or `@bar {json}` in the question's `explanation`, and the player draws it (`WorkedPicture.tsx`); edit it as text in the question editor.

`npm run deck -- build <script>` builds the deck, runs the checks and writes `src/decks/data/<id>.json` (it refuses to overwrite an existing deck without `--replace`, since that file may hold edits made in the player: pull first). `npm run deck -- check <id|all> [--layout]` runs the content checks (maths renders, answers where the working ends, sets of at least 5, Depth cards ask new numbers, generators run at their level and do not pile on one answer, text fits its box) and with `--layout` also starts the app and measures every slide. The same checks run in the tests for every built deck (`deckBuilder.test.ts`). House rules for what to build: `docs/design/LESSON_STYLE.md`. <!-- ref -->

### Sharing one deck between Harry and Claude (merging)

Two people can edit one deck. `api/_deckMerge.ts` is a pure three-way merge (base, incoming, current) by slide and by element, then field by field within an element: a change on one side is kept, edits to different things on both sides are both kept, an edit beats a delete, additions on either side are kept (ordered after the item they followed), and when both changed the very same field the winner's value is kept and the clash is reported. The winner is Harry (the editor's saves are `incoming`; Claude's pushes are `by: "Claude"`, so the stored copy wins). The merge is used in three places:
- **The server** (`POST /api/decks {deck, base, by}`): reads the stored deck with its ETag, merges the save into it, writes with the ETag (retrying if another save got in first), and answers `{merged, conflicts, deck}`; a merged deck gets a new `updatedAt`, so every device picks it up. A save with no `base` replaces the deck, as before. Every response carries `x-deck-merge: 1`.
- **The editor** (`store.ts` keeps each deck's base in `mt-deck-base:<id>`: set each time a deck is pulled or a save is accepted; the first copy a page saw is used until then). A save sends it; the server's merged deck is folded into what is on screen (`takeShared`: the undo history gets the same changes, so an undo does not take them away), and the editor looks for other changes only when asked (File → **Check for changes**, `checkForUpdates`: one read of that deck, no polling, so an open editor does not keep the database awake). A save that adds nothing to the base is not sent.
- **`npm run deck`**: `pull` writes `.deck-base/<id>.json` (git-ignored); `push` sends it, takes the merged deck back as the file and prints any clashes, and refuses to run if the service does not send `x-deck-merge` (an older deployment would overwrite the whole deck) or if there is no base (`--replace-whole` is the deliberate overwrite). **The live copy is the master and the repo file is its snapshot:** `check <id|all> --live` checks the live copy directly (and with `--layout` draws that copy, not the repo's; nothing in the repo is read or written); `backup [<id>|all]` writes the live copies into `src/decks/data` (a file with unpushed edits, i.e. one that differs from its `.deck-base`, is left alone and reported); `publish <id>` publishes the live copy (`--file` publishes the repo file) and then backs it up. Commit the snapshots so git keeps the history and the tests have the data; the app only uses them as the first-run fallback.
- **Slide order is not merged: the stored order wins.** Moving a slide in a pushed file is silently undone, and after any merged push the CLI writes the merged deck back over the file (so re-apply a move after a push). To reorder: pull, confirm the shared copy has not moved since (compare it with `.deck-base/<id>.json`), make the move, delete `.deck-base/<id>.json` and push with `--replace-whole` (no base means the file replaces the whole deck), then read the shared copy back to check the order.

Tests: `deckThreeWayMerge.test.ts` (the rules, and the real Manipulating ratios case), `decksSave.test.ts` (the server path against an in-memory Postgres (`src/tests/testDb.ts`, PGlite), either order, retry), `decksStore.test.ts` (list, delete, publish and its cache, questions, two saves at once), `migrateDecks.test.ts` (the Blob import), `deckSync.test.ts` (the base, adoption).

### Fitting the screen on a tablet

The player and the editor are as tall as the screen the person can actually see (`useVisibleHeight`, `src/shared/visibleHeight.ts`, with the `.h-app` class in `index.css`): the page height follows `window.innerHeight`, so a tablet browser's address bar no longer pushes the bottom of the slide, or the player's bar, off-screen, and the slide scales to fit what is visible. (The old `h-screen`, `100vh`, is the page with those bars hidden.)

### Zooming the editor's slide

The slide can be enlarged (to 600%) so a box on it is big enough to write in, or shrunk (to 30%) to see it small; 100% is the whole slide fitted to the window. **Two fingers pinch to zoom in or out and, moving together, pan**; **Ctrl + scroll** (and a trackpad pinch) zooms at the pointer; the **+ / − and % buttons** at the bottom right of the canvas step the zoom, and the % button fits the whole slide again. The slide is drawn at the larger size inside a scrolling area (`stageRef`; `scale = fitScale × zoom`) instead of being magnified as a picture, so lines stay sharp and drawing, dragging and handles use the same coordinates as at 100%. A second finger cancels anything the first had begun. On a touch screen where a stylus has been used, the stylus writes and one finger pans; without a stylus one finger writes. Zoom is a view setting only: it is not saved with the deck and stays when you change slide.

### The timer

A countdown of 1 to 10 whole minutes, drawn as a strip under the slide in the player (the player scales the slide down to make room, so the strip does not cover content) (a line that shrinks, amber in the last quarter and red in the last tenth, with the time, a pause or play button and a close button at the right; at zero it reads Time and the line pulses). Logic in `timerMath.ts` (a countdown is its total, the seconds left when last paused and the clock time it ends at, so the redraw rate does not matter), parts in `Timer.tsx`. **Callable on any slide:** the clock button in the player's top bar (or the full-screen control pill) opens a menu of 1 to 10 minutes and choosing one starts it at once; `T` opens the menu, or pauses and resumes a timer that is already showing. **On a slide:** `Slide.timer = { minutes, auto? }` (Slide settings → Timer in the editor, or `S.starter(id, title, minutes)`): the strip appears with the slide and starts at once unless `auto` is false. A timer belongs to the slide it was started on: moving to another slide clears it. Slide timers are checked by the deck check and the decks API.

### Writing: saved on a slide, and kept while a deck is open

Two separate things. (1) The editor's **Pen** writes into the slide itself (the `ink` element above), so it is saved with the deck and seen by everyone. (2) The player's pen (the app-wide `InkOverlay`) is Harry's live annotation: its strokes now **stay with their slide while the deck is open** (`DeckPage` reads them through `src/shared/inkBridge.ts` when you leave a slide and puts them back when you return, in slide units, so a resize or full screen moves them with the slide) and are gone when the deck is closed. Moving between questions inside a slide still clears the pen, as before.

## Automatic text sizing, and the manual override

Text that has a predetermined size fits its box by default, and any of it can be set by hand. An element's `size` is the **most** it will be while Auto is on; `fixed: true` is the manual override, drawn at exactly `size`. Pressing bigger or smaller or typing a size in the editor sets `fixed`; **Auto** (the toolbar pill, **Auto size** in the panel) turns fitting back on. The number shown is what is on screen (elements report the size they are drawn at, `src/decks/shownSize.ts`, from the editor canvas only), so the first press of bigger or smaller starts from the fitted size, not from the maximum. Steps are 2 below 40, 4 to 79, 6 from 80; the size box goes down to 12 (under 26 shows amber).

| Element | Auto | `fixed` (by hand) |
|---|---|---|
| `text` | is the largest whole size (found by bisection, not 7% steps; down to 20) at which the text is no taller than 75% of its box (`FIT_FILL` in `SlideCanvas.tsx`: the one number to change); boxes with the same role (titles 60 and over, body 40 to 59, labels under 40) share the smallest | exactly `size`; the content check reports a text that does not fit |
| `maths` | the largest size at which the equation fills no more than 75% of its box (`FIT_FILL`) | exactly `size` |
| `grid` (quickfire, retrieval, exit ticket, hand-written book work) | drawn in the same cells as a book activity (`BookCell`); is the largest size at which the question (and, separately, the answer) fills no more than 75% of its cell's width and height (`BOOK_FILL`), whatever `size` was saved | exactly `size` (the question is drawn at 0.7 of it) |
| `worksheet` (book activity) | is the largest size at which the question (and, separately, the answer) fills no more than 75% of its cell's width and height (`BOOK_FILL` in `SlideCanvas.tsx`: change that one number to make Auto bigger or smaller) (a book-work sum stays on one line: `.deck-nowrap`) | exactly `size` |
| `board` | the **header row and the body are fitted separately** (a long heading does not shrink the numbers, nor the reverse); each cell's text is at most 75% of its row's height and fits its column, measured on the filled-in table so revealing does not change it | exactly `size` |
| `questions` | shrinks from `size` (capped at 64) until the question and working fit | exactly `size` (to 140), no cap and no shrink |
| `generator` | a long worded question is set smaller (`wordedSize`) | the question at exactly `size`, the working at about 0.45 of it |
| `ratioTable` | scales down to fit its box | no scale-down: the cell text is exactly `size` |
| `bar` | fits its box by itself; `size` is the text size, set by hand (no Auto) | |

**Answers have their own size** on a book activity (`worksheet`) and a `grid`: `answerSize` and `answerFixed`, fitted on their own (by default up to the question's size) so a short answer is not shrunk to the question's size, or the question to the answer's. In the editor the toolbar's **Questions | Answers** switch shows every book activity and grid on the slide with its answers up (`forceAnswers`, not saved), and the size control and **Auto** then set the answer size. Question and answer text are measured separately by `data-part="q"` / `"a"` (`partOverflows`).

The content check only reports a text box that cannot fit even at the minimum (26). Do not add per-slide shrink helpers to a build script, and do not set sizes by hand in one. <!-- ref -->

Presenting, a Depth card has one click: Next shows the answer and Back returns to the question (the button and `a` also work). Depth-shaped questions written in the deck (claims, choices, a mistake to find) are drawn by the same slide, so every Depth face looks alike. A deck's Depth card is a `kind: "depth"` reference; to customise a card for one lesson, write an ordinary question (Questions) instead. <!-- ref -->

Every button drawn on a slide (Show answers, New question, Show working, Previous / Next question, the Depth slide's controls) uses `slideButton` (`src/decks/slideButton.ts`): 26 slide units of text in a 48-unit-tall button. Use it for any new slide button instead of styling one by hand. <!-- ref -->

## Rebuilding without losing edits, versions, layouts and templates

- **A rebuild keeps your edits.** Every slide a build writes carries `built`, a hash of the slide as built (`src/decks/merge.ts`). `npm run deck -- build <script> --replace` replaces only slides whose hash still matches, keeps edited slides and slides added in the editor (in place), drops built slides that were not edited and are no longer in the script, and prints what it kept. `--force` overwrites everything. A deck built before slides were stamped is replaced once, and is safe from then on. `npm run deck -- diff <id>` (after a pull) lists the edited and added slides, so what was changed can be learned from, not overwritten.
- **More commands:** `preflight <tool>`, `verify <id>`, `builders`, `sheet <id> 7,13,20` (one picture of those slides), `new <id> <tool>` (preflight plus a build-script skeleton).
- **Version history (editor, File).** Up to six snapshots per deck are kept on the device: one while editing (every ten minutes), one before an update from another device replaces the local copy, and any saved by hand. Restore puts one back and can be undone. <!-- ref -->
- **Layout (editor, top menu)** changes the open slide to another layout and carries its content over (texts to texts, questions to questions, a picture to a picture); anything with no place in the new layout stays where it was. **Save as a template** (Slide menu) keeps a slide on the device, and it then appears under *My templates* in Add slide.

## Printing slides

`PrintSlidesDialog.tsx` (File → Print slides…, and **Print slides** in the player) prints chosen slides 1, 2, 4 or 8 to an A4 sheet, each slide 1 to 8 times (`repeatSlides`); the page is shared into equal slots with each slide centred in its slot, and faint dashed cut lines (`cutLines`) run between slots, so 2 to a sheet cuts exactly in half; **Fill to edges** (`slotAlign`) instead pushes the outer rows and columns to the page edge so the spare paper falls at the cut; the sums (grid, page turn, millimetre sizes, key-point families) are in `slidePrint.ts` and tested in `slidePrint.test.ts`. The pages are drawn into a hidden `#slide-print` area of the page, and the browser's print hides everything else (`body > *:not(#slide-print)`). Each slide cell has `contain: strict`, or Chromium shrinks the whole print to fit the 1600-wide canvas inside it. <!-- ref -->

A `grid` or `worksheet` element has `align`: `left` (the default) or `center`, set under **Questions in their cells** in the toolbar's **Style** menu. It positions the question, and the answer that replaces it, within the cell; the number stays at the left. <!-- ref -->

**Where the controls live.** The ribbon holds every setting, including content: a table's cells, the generator and worksheet settings and a text box's words open as popovers from Home (`Menu` with `panel`, 460 px wide). Home formats what is selected, Insert adds things, Design is the slide's own settings, Arrange is placement. The right-hand panel holds one thing: the list of what is on the slide (`ObjectList`), to pick a thing or change what is in front. <!-- ref -->

**Flowcharts** (`flowchart.ts`, tested in `flowchart.test.ts`): `flowchartEls(prefix, nodes, edges, area)` returns ordinary shape, text and line elements for a flowchart (steps as boxes, questions as ovals, Yes and No results in green and red, arrows between them), so it saves, shares and prints like anything else and each part can be moved by hand afterwards. Nodes sit on a grid (`col` may be fractional), take an optional `step` (the click on which the node appears; an arrow appears on the later of its two ends' clicks, so a loop back to an earlier box waits for the box it leaves) and an optional size; an arrow between nodes not in line bends once (`route` "hv" or "vh"). The Primes and divisibility deck uses it for the rules for 3, 11 and 7, each on a key point slide (family `language`) beside the rule and an example. <!-- ref -->

**The full-screen controls** (`PlayerBar.tsx`): one small bar, the same on every slide so it never changes size: a grip, Back, the slide count, Next, **Slide options** and **Leave full screen**. What a slide can offer (how much of a board, table or picture is filled in, a timer, Jump to a slide, Print slides, the 1 to 100 grids and a book activity's sheets) is in the Slide options pop-out (the timer's minutes in two rows of five). The grip drags the bar along the bottom (its place is remembered on the device); it keeps its right edge out of the ink pencil's corner (`barLeft`), and rises above the ink pencil or hotbar if one is in its way (`liftAbove`; the ink controls carry `data-ink-bar`). It fades out when the mouse rests, and stays while the pop-out is open or it is being dragged. The deck list (`/decks`) has no description or sync line under its title. <!-- ref -->

Authored rectilinear worksheets print four questions per A4 page with two rows of working space, plus a matching worked key. Generated diagram sheets keep six per A4 page. The Year 7 rectilinear lesson has twelve authored questions across three pupil pages.
