# Decks — whole lessons, and the slide editor

**Read when:** Building or changing a deck, a slide layout, a deck element, a slide-owned question set, the player or the editor. For the shape and house style of a whole deck, also read `docs/design/LESSON_STYLE.md`.

A **deck** is one combined, directed lesson for the projector, played at `/decks/<id>`. It is also a small slide editor, a stripped-down PowerPoint around the site's own pieces: a teacher can refine a deck Claude built, add slides to it, or build their own. Decks wrap what the site already has (generators, authored question sets, boards), so a lesson stays in one place; tool pages are unchanged. Decks are the intended successor to the per-tool Teach deck and Lessons modes. Plan: `docs/pathways/decks.md`.

## Pages

| Address | What |
|---|---|
| `/decks` | The deck editor's list: every deck (built, edited on this device, and the teacher's own), **New deck**, the Slide library link, and a "published" mark. **Needs the admin password** |
| `/decks/library` | Every slide layout with sample content, grouped by family, plus the planned pieces. **Needs the admin password** |
| `/decks/<id>` | The player. Anyone sees the **published** copy, read-only (no Edit). With the password it shows the working copy, with **Edit** (`?edit=1`, password needed) and **Present** returning; `?published=1` shows the published copy to an admin |

Reached from the landing page's **Decks tab** (`/?tab=decks`): the published decks as cards (the first slide as a preview, kept in the published listing so the tab loads no decks), and a **Deck editor** button that asks for the password. The tool's burger menu also lists "Deck: <title>" in Developing-tools mode (`decksForPath`).

## Published decks (`published.ts`, `AdminGate.tsx`, `api/decks.ts`)

- **Publishing** is a button in the editor's File menu (**Publish this deck**, **Publish again**, **Unpublish**; `npm run deck -- publish <id>` does the same from the command line). It sends a frozen copy of the deck, with its questions embedded, to its own blobs (`published/<id>.json` and `published-index.json`); the working copy is untouched and later edits change only the working copy until it is published again.
- **Reading is open to everyone** (`GET /api/decks?published` and `?published=<id>`); everything else on `/api/decks` still needs the admin key. The landing page's Decks tab and the read-only player read only the published copies, never the working copy or this device's saved edits. <!-- ref -->
- **The password** is the Developing-tools password and the same switch: entering it at the editor's prompt turns Developing-tools mode on, and turning that off locks the editor again. It is a light check, not security: the string is in the site's code (`src/devAccess.ts`).
- Published decks come from the website, so the local dev server and an offline device show "can't be listed here". `npm run smoke:published` checks the whole flow with the service simulated. <!-- ref -->

## The model (`src/decks/types.ts`)

- A **deck** is `{ id, title, summary, tool?, toolPath?, slides }`.
- A **slide** is `{ id, family, title, brief?, els }` (`brief` is the optional slide brief; older decks' `intent` / `questionBrief` are folded into it by `withBriefs` when the editor opens a deck): a canvas `CANVAS_W × CANVAS_H` (1600 × 900) units, scaled to fit. The family sets its accent bar (`FAMILY_STYLE`; none is green, yellow or red, the level colours); the title names it in the jump list and the slide strip.
- An **element** is a box (`id, x, y, w, h` in canvas units; a line runs from `(x, y)` to `(x + w, y + h)`, so its `w`/`h` may be negative) and one of:

| `kind` | What | Notes |
|---|---|---|
| `text` | Text, `$…$` inline maths, a new line per line | `size` (≥ `MIN_TEXT` = 26), `bold`, `colour`, `align`, `middle` |
| `shape` | Rectangle or ellipse | `fill`, `stroke`, `strokeWidth`, `radius` |
| `line` | Line or arrow | `colour`, `width`, `arrow` |
| `image` | A picture, stored as a data URL | Large images are scaled to the canvas and saved as JPEG on upload |
| `maths` | An equation on its own | `latex`, `size`, `colour`, `align`; made and changed in the equation editor |
| `ratioTable` | The site's ratio table (`RatioTable`): quantities as columns, a row per scale step, the factor between two rows as an arrow outside the table | `table` (`headers`, `rows`, `operations`: one LaTeX factor such as `\times 2` between each pair of rows, `given`), `fill` as a board (Structure only keeps the headings and the given rows and hides the arrows; empty cells draw as "?"), `size` (cell text size), `staged` (one more row, with its arrow, per click). The table is laid out at its **full size** from the first click, with later rows hidden in place (`hideFrom`), and fitted to its box once from the whole table, so a four- or five-step table never rescales or moves as a row arrives | <!-- ref -->
| `bar` | The site's bar model (`BarModel`, `src/shared/barModel.ts`) in two looks: the **ratio look** (`rows`, the stacked layout Ratio Sharing uses: a row per quantity aligned from the left, white boxes with a navy border, a value in each box, "= total" at the end, purple extra boxes for a difference, a brace across the rows) and a **single bar** of coloured parts with braces above or below (for fractions) | `bar` (`rows`: name, units, `unitLabel`, `total`, `extraFrom`, `known`; `sideBrace`; or `parts`: units and tone; `braces`: from, to, label, below; `unitLabel`), `fill` (Structure only: the coloured boxes without braces or labels; Blank: empty boxes), `size`, `staged` (rows: one row per click, then the brace, then every value and total together; single bar: one part per click, then one brace per click; the layout is fixed from the whole bar so nothing moves) |
| `board` | A table to write on | `grid` (`head`, `rows`, `given`), `fill` (Filled in / Structure only / Blank: a control in the player bar; B cycles modes), `size` |
| `questions` | A curated sequence of deck-owned questions | `items: CuratedQuestion[]`, optional `size`, shared `presentation` and `visualiser`; open response, multiple choice, compare claims, find the first error |
| `practice` | Legacy bank references | Read for compatibility; converted to deck copies when editing/exporting. Generator fallback is no longer used. |
| `grid` | Several open-response questions at once | Embedded `items`, `cols`, `size`; the answer replaces the question in its box (all at once with Show answers or `a`, or one box with a double-tap); legacy `bank` references remain readable. Rich diagnostics belong in a Questions activity. |
| `generator` | The tool's generator live, like its Whiteboard | `tool`, `preset` (`sub`, `level`, the tool's Question Options), `seed` (the first question, the same every time), `prompt` (blank: the tool's instruction); New question, the shared solution stepper, the answer (keys `n`, `s`, `a`); shared `presentation` (`full`, `whiteboard`, `whiteboard-inverted`) and optional `visualiser` select the saved display layout |
| `worksheet` | A book activity: `count` generated questions, numbered | `tool`, `preset`, `count`, `cols`, `seed`; answers on demand (shown in place of each question, like the worksheet), a **double-tap** on a cell flips just that cell, a small regenerate button on each cell (hidden until the activity is pressed, then it fades after a few seconds) replaces that one question with a new one that is not already on the slide, and New set (no Print button); `size` defaults to 60. A worded question shows its maths line at full size, and an instruction shared by every question is shown once above the set |
| `depth` | One of a tool's Depth items, drawn flat on the slide in the deck's style (`DepthFlat.tsx`) | `tool`, `item` (an id in the tool's `__test.depthItems`); Show answer turns it to the answer in place |

Any element may carry `step` (1, 2, …): it appears on that click when presenting (Next reveals a slide's next click before moving on; Back hides it). The split discussion layout uses it for its fixed order: prompt, key point, question, answer. The ratio table and bar model share the board's Filled in / Structure only / Blank control in the player bar (B cycles). Still to come: the other core representations (place value table, number line, area model, algebra tiles, counters, prime factor tiles), a timer, match-up and sort (listed as "Planned" in the library). Generator slides draw a ratio-table or fraction-bar working step as its picture (the bar scaled to fit its panel, a long worded question set smaller so it fits); fixed questions cannot hold one yet.

## Worksheets pinned to a lesson (`worksheets.ts`, `WorksheetsDialog.tsx`)

A lesson can pin up to three printable worksheets (`MAX_PINNED`). A pinned worksheet is an ordinary book-activity element (`kind: "worksheet"`) with `pin` set (`title`, `paper` A5 or A4, `layout` grid or list, `borders`, `fontPx`), so saving, sharing, undo, copy and export need nothing new. It prints through the same layout engine as the tool pages' Worksheet (`handlePrint`, `src/shared/print.ts`) on an **A5 page** by default: questions, an **answer sheet** (a compact numbered list in larger type, measured from its own items: `compactAnswers`), or both. A5 pages print two to an A4 sheet with "Pages per sheet: 2" in the print window. `frozen` keeps the generated questions (working left out, with a `sig` of tool, setup, count and seed) with the deck, so a printed sheet and its answers do not change if a generator does; it applies only while the setup matches, and otherwise the same seed regenerates the same set. <!-- ref -->

- **Pin it:** tick *Pin to the lesson* on a book activity (properties panel: title, page, layout, borders, text size, **New set**, **Print**, **Answer sheet**), or Add slide → **Worksheet**, which starts a pinned slide and opens the generator setup.
- **Print it:** File → **Worksheets…** lists the pinned sheets with Print, Answer sheet and Both.
- **Getting to them:** a **Worksheets** button sits in the top bar of both the player and the editor (shown only when the lesson has pinned sheets) and opens the same window as File → Worksheets…; on a worksheet slide the player's bottom bar also has **Print sheet** and **Answer sheet** buttons.
- **On the slide:** a pinned worksheet can show **the answers** (`view: "key"`, the Worksheet layout's default): numbered answers hidden until `a`, the cue to hand the sheet out. Showing the questions (`view` absent) draws the book activity, without its New set button so the slide always matches the paper. <!-- ref -->
- A worksheet carries no scaffold; the questions fill the page and pupils answer in their books.

## Layouts (`src/decks/layouts.ts`)

A layout is a function that returns a pre-arranged slide of ordinary elements: title, learning objective, section divider, summary, key vocabulary, key definition, two columns, board, skill practice, quickfire block, Depth card, split discussion, retrieval starter, exit ticket, blank. Families: Lesson (structure), Language, Teach, Practice, Depth, Discussion, Retrieval. `LAYOUTS` lists each with its sample content and when to use it; the editor's **Add slide** and the library both read it, and the built decks are written with the same functions (so a built deck and a teacher's slide are the same kind of thing). Add a layout only when a lesson needs it, after checking none in the family does the job.

## Built decks, edits and the teacher's own decks (`src/decks/store.ts`)

- **Decks are data** (`src/decks/data/<id>.json`, loaded by `index.ts`; the deck holds its own `tool` and `toolPath`). The shared copy (cloud) is the master, because Harry edits there: Claude runs `npm run deck -- pull <id>` first, changes the JSON by slide id, then `npm run deck -- push <id>` (`npm run deck -- list` shows what is shared). Push only a deck you have just pulled. The JSON in the repo is the snapshot a fresh device starts from. Slide ids are stable (`<deck>-<slug>`). <!-- ref -->
- **Edits are saved on this device** (localStorage) as the teacher makes them: an edited built deck is saved whole under `mt-deck:<id>` and **Reset** returns it to the original; a teacher's own deck (`my-…`) is listed in `mt-decks-mine`. Question copies are embedded in each deck. Editing them changes that deck only and participates in deck undo. `mt-deck-bank` retains old personal library records for legacy reference resolution. Ordinary authoring has no library browse or save action. <!-- ref -->
- **Export** materializes legacy question references and downloads the complete question content, including misconception descriptions and teaching guidance, as JSON; **Import slides** appends a file's slides to the open deck. Copy / paste (Ctrl+C / Ctrl+V, or the slide's Copy button and "Paste a copied slide") works between slides and between decks.
- **Shared between devices** (`src/decks/cloud.ts`, `api/decks.ts`, `api/_decks.ts`): every save is sent in the background (a moment after the last change) to `/api/decks`, which keeps each deck in its own private Vercel Blob (`decks/<id>.json`), an index (`decks-index.json`) and the shared questions (`deck-questions.json`); the index and questions are written with their ETag, like the dashboard notes. Opening the deck list or a deck pulls any copy newer than the device's (`syncFromCloud`, comparing the deck's own `updatedAt`); nothing is pulled while editing. Header `x-admin-key` as for `/api/tool-notes`. A deck over 4 MB (large pictures) is refused with a message. Where the service is not reachable (the local dev server, no connection) the decks keep working on the device and the status line says so.

## Building a deck quickly (`builder.ts`, `deckChecks.ts`, `npm run deck`)

A new deck is a short script, kept outside the repo (the scratchpad), that default-exports a function returning the deck. `S` makes slides (title, board, deliberate practice, general practice generator, book activity, quick grid, Depth card, discussion…) and `Q` makes questions with the tool's own working (`Q.rounding`, `Q.estimate`, `Q.fraction`, `Q.open`); each `Q` builder writes the working the tool does, so only the numbers are typed.

```ts
import { Q, S } from "/src/decks/builder";
export default () => ({ id: "my-deck", title: "My deck", summary: "…", tool: "estimation", slides: [
  S.title("m-title", "My deck", "Round first"),
  S.deliberate("m-set", "Estimate products", [["42", "18"], ["63", "29"]].map(([a, b], i) => Q.estimate(`m-${i + 1}`, "level1", a, "\\times", b)), "Brief."),
  S.general("m-gen", "Whiteboards", "estimation", { sub: "estimation", level: "level1" }, 3),
] });
```

Fixed questions that carry a tool's own working: `Q.ratioSimplify(id, level, parts, ask?, method?)` and `Q.ratioFraction(id, level, spec)` make a question with the Ratio Manipulation generator's code (fixed numbers, wording chosen with `variant`) and check its answer from the parts; `fromWorked` (`questions.ts`) turns any generated question into a fixed one. A working step that is a picture (a ratio table growing a row per step, the fraction bar model) is kept as a line `caption` + newline + `@ratiotable {json}` or `@bar {json}` in the question's `explanation`, and the player draws it (`WorkedPicture.tsx`); edit it as text in the question editor.

`npm run deck -- build <script>` builds the deck, runs the checks and writes `src/decks/data/<id>.json` (it refuses to overwrite an existing deck without `--replace`, since that file may hold edits made in the player: pull first). `npm run deck -- check <id|all> [--layout]` runs the content checks (maths renders, answers where the working ends, sets of at least 5, Depth cards ask new numbers, generators run at their level and do not pile on one answer, text fits its box) and with `--layout` also starts the app and measures every slide. The same checks run in the tests for every built deck (`deckBuilder.test.ts`). House rules for what to build: `docs/design/LESSON_STYLE.md`. <!-- ref -->

## The player (`DeckPage.tsx`, `SlideCanvas.tsx`)

Arrow keys, Page Up/Down and Space move slides; Home and End jump; `j` opens the jump list; full screen. Curated activities have **Previous question**, **Next question**, a question count and an explicit end of sequence. Answers start hidden on every question. **Show working** moves the question smoothly from the centre to the right and opens the unfolding solution on the left. Previous / Next step, with **Show all / Step-by-Step** between them, navigate its numbered timeline (the step count sits beside the Worked solution heading); earlier steps dim, the newest is highlighted, and the final answer has a green A marker. **Show answer** (`a`) jumps to that final solution; `w` advances one beat; The player has no teacher-guidance button and no More menu; guidance stays in the editor's Teaching details. Choices and worked lines can be selected before the reveal. Curated sequences never fall through to a generator; add a generator activity separately. Answer notation belongs to the authored content (Estimation explicitly includes approximation). Curated questions, generator questions and workspace previews share `src/shared/components/SolutionStepper.tsx`. The question stays in the same DOM node during the move. Hiding the working returns it to the centre; changing question clears solution progress. Long solutions follow the newest step inside their own column, keeping question and navigation in place. A narrow popup stacks question above working; the 16:9 classroom canvas keeps the split. Reduced-motion preferences disable the drift and fades. Ink clears on a question or slide change. <!-- ref -->


## The editor (`Editor.tsx`, `EditorPanels.tsx`, `geometry.ts`, `EquationEditor.tsx`)

The slide strip on the left, the canvas in the middle, the selection's properties on the right. The chrome lives in `EditorChrome.tsx` (`usePref`, `Menu`, `MenuItem`, `MenuDivider`, `BarDivider`, `ShortcutsDialog`, `Section`, `Splitter`, `SlideStrip`, `ObjectList`); the canvas and editing in `Editor.tsx`.

- **Panels:** both side panels hide and show (header toggles, the View menu, or `\` for both), resize by dragging their edge (double-click resets), and remember their width and open state on the device (`usePref`, keys `mt-deck-*`). The canvas refits by itself.
- **Slide strip:** a finder (matches a slide's title, kind and the words on it), pictures or a compact list (the list scales to 28+ slides), drag to reorder (not while filtering), hover to duplicate or delete, and the open slide scrolls into view. A bare "Practice" title shows the misconception it targets (`slideLabel`). **Add slide** is grouped by kind, with a line saying what each layout is for.
- **Header and toolbar:** two rows across the top. The header holds a back arrow to the deck list, the deck's name, the save status, the panel toggles, **Lesson thread** and **Present**, and a menu bar: **File** (export, import, present from this slide, back to all decks, reset or delete), **Edit** (undo, redo, copy, paste, duplicate, delete, select all / nothing, each with its key), **Insert** (text, equation, image; shapes and lines; the lesson pieces with a line each), **Slide** (duplicate, copy, paste, move earlier / later, delete, previous / next, Lesson thread) and **View** (show the slide list and properties, the strip as pictures or a list, keyboard shortcuts). The toolbar below has undo / redo, **New slide** (the layouts, grouped by kind), Text, Equation, Image, **Shapes** and **Questions** (the lesson pieces); then what depends on the selection: with nothing selected, previous / next slide and "Slide n of N"; with an element selected, its quick controls (text: size, bold, alignment, colour; equation: edit, size, alignment, colour; shape: fill, outline; line: colour, arrowhead; question sets and generators: edit / configure), **Arrange** (line up, space out, layer), duplicate and delete. Labels drop to icons on narrower screens so the toolbar fits on one line at 1024px; the full controls stay in the properties panel. `?` opens the keyboard shortcuts window. On a phone the slide gets the screen: both panels start shut and only one opens at a time.
- **Connecting a slide to the site** (`EditorPickers.tsx`): **ToolPicker** supplies searchable, strand-grouped tool selection inside the central generator dialog. That dialog owns the preset controls and live preview. Fixed questions are authored in the slide-owned Skill practice workspace, and Depth cards retain their separate picker. Dropdown menus are positioned on the screen (`Menu`), so a panel cannot clip them.
- **Pictures:** paste an image straight from the clipboard (a screenshot, a copied picture) or drop an image file onto the slide; the Image button still opens a file. Paste is the browser's `paste` event (not the Ctrl+V key), so a copied image arrives as a file; otherwise Ctrl+V pastes copied elements or a slide as before. Large pictures are scaled down and saved as JPEG (`readImage`).
- **Properties:** the selection's own controls come first; the rest are collapsible sections that remember open or shut (Click order, Line up and layer, Position and size, **On this slide**). **On this slide** lists every element front first, click to select (Shift adds), arrows change the layer: use it to find something hidden behind something else.

- **Select:** click; Shift-click adds or removes; drag on empty space draws a selection box; Ctrl+A selects the slide.
- **Move and resize:** drag; pull the handles (a line has one at each end). Pink **smart guides** appear when an edge or centre lines up with the slide's edges or centre lines or with another element, and the element snaps to them; otherwise positions snap to a 10-unit grid; hold Alt to place freely. A picture keeps its shape from a corner (Shift to stretch). The geometry is pure and tested (`src/tests/deckGeometry.test.ts`).
- **Line up:** left / centre / right / top / middle / bottom, against the slide (one selected) or the selection's box (several); space three or more evenly across or down; layer (front, forward, back, behind all).
- **Type on the slide:** double-click a text box (or Enter with it selected) and type into it in place; the box grows to fit; Esc or a click elsewhere finishes; the whole edit is one undo step. A new text box opens ready to type.
- **Equation editor:** a visual maths field (MathLive 0.111.0, loaded only when it opens and using the KaTeX fonts the site bundles, so no CDN): type `/` for a fraction, `^` for a power, arrows between boxes; a palette of structures (fraction, mixed number, power, root, brackets, column vector, standard form, recurring dot) and symbols; the LaTeX underneath. It adds an equation element, edits one (double-click), inserts `$…$` at the caret of the text being typed, and opens from the question editor's fields. The result is checked with KaTeX (what slides use) before it can be used.
- **Click order:** "Appears when presenting" sets an element's `step`; the canvas shows a numbered badge.
- Keys: Delete, Ctrl+Z / Ctrl+Shift+Z, Ctrl+D duplicate, Ctrl+C / Ctrl+V (also between decks), arrows nudge (Shift for 1 unit), Page Up/Down change slide. Every `$…$` and question field is checked with KaTeX as it is typed; a question cannot be saved with broken maths, and incomplete questions can be saved as drafts. Text under `MIN_TEXT` is flagged as too small for the back of the room. Undo / redo keep 100 steps for the session.

### Generator configuration

Generator questions and book activities use the central **Configure generator** dialog (`src/decks/GeneratorDialog.tsx`). New generator elements and generator layouts open it automatically; existing elements have a **Configure generator…** button in their properties and open on double-click. The side panel keeps a setup summary and the element’s placement controls.

The dialog loads the tool’s own tabs, available levels and Question Options, with spacious option groups, the shared level selector and a scaled slide preview. Book activities also offer question count and columns; generator slides and activities can override the instruction and choose a different first question or set. Optional pools may be emptied; other pools keep at least one choice, and dependent options are disabled until their requirements are met. Switching a question type selects a supported level. The Rounding tool is available here for its three rounding sub-tools (not Identify Sig. Figs): its digit-box working is drawn by the slide (`RoundDigits`, shared with the tool).

Configuration stays in a draft until **Apply to slide**, which saves it as one undo step. **Cancel**, Escape and clicking the backdrop discard the draft. The native modal dialog traps focus and makes the editor inert; editor keyboard shortcuts are suspended while it is open. At narrow widths the controls and preview stack, with the actions kept visible.

### Shared question layouts

**Questions** groups Fixed question set and Live generator in Add slide and the slide library. Depth card retains its own entry and picker. The content workflows remain distinct; each uses the same illustrated **Question layout** selector in its central editor. Grids, book activities and other layouts remain separate. Workspace display is a presentation choice, rather than a separate Whiteboard generator entry.

| Saved presentation | Editor label | Classroom arrangement and reveal |
|---|---|---|
| absent / `full` | Full-width | Question fills the area, then moves right while steps unfold left |
| `whiteboard` | Workspace right | Question left, writing/camera space right; question contracts upward and steps unfold beneath it |
| `whiteboard-inverted` | Workspace left | Writing/camera space left, question right; question contracts upward and steps unfold beneath it |

The optional `QuestionDisplaySettings` fields live on ordinary `questions` and `generator` elements, independently of their contents. Depth cards override these settings and remain standalone. The API validates the same settings for both. Existing whiteboard generator flags retain their meaning. The editor’s Apply saves display changes together with the content as one undo step; Cancel/Escape discards them, and draft recovery includes them. Display settings survive duplication, save/share and portable export/import. The classroom has no layout selector. The slide brief and question content stay unchanged when presentation changes.

`QuestionFrame` supplies the common arrangement, with `WhiteboardWorkspace` as its writing/camera panel. For a fixed set, the frame sits outside the per-question key, so question navigation resets the solution and clears ink while retaining the active camera. Revealing working preserves workspace geometry, camera and ink. Generator slides use the same frame and canonical stepper. `SolutionStepper` still uses `split` for full-width and `stacked` within a workspace question panel. Narrow previews and reduced motion remain supported.

Camera controls live behind one **Workspace options** ellipsis in the panel corner. Start visualiser, Stop visualiser and the device selector appear inside that menu; the workspace has no permanent header or device strip. Editors offer a camera-availability checkbox for workspace layouts. Permission errors provide Retry, with Stop still available through the menu. Camera activation is explicit; editor/configuration previews and thumbnails request no camera. Tracks are stopped on unmount, replacement and late asynchronous acquisition. Camera permissions, streams and device IDs stay out of saved deck data. The feed is fitted without cropping.

The player uses 8px outer padding. Shared panels have a 16-canvas-unit gap and 12-unit question padding. New full-slide fixed sets, generators and Depth layouts use 24-unit insets; older saved custom positions remain unchanged. Slides retain the 16:9 ratio and existing fullscreen controls.

## Slide-owned question editor

**Fixed question set** (Add slide; **Questions → Skill practice** in the toolbar, **Edit questions** on the selected element, or double-click) opens `QuestionWorkspace.tsx` on this slide’s ordered set. Three columns on a laptop: the questions down the left (numbered, unfinished ones in amber, **Add question** under them), the selected question’s fields in the middle (**Question**, **Answer**, **Worked steps (one reveal per line)**, each with a small **Σ Insert maths** link; duplicate, move earlier / later and remove as icons beside its heading; **Teaching details · optional** for title, tool / level, other formats and misconception guidance), and the classroom preview on the right with the layout switch (Full-width, Workspace right, Workspace left) above it. Below a laptop the columns stack and the list scrolls sideways. The header holds the slide title and the slide brief (one optional box) with **Copy for chat**, which copies the deck, slide id, title and brief as plain text. Grids offer open-response content. There is no bank browser, source filter, library registration or Save to library.

**Apply to slide** saves title, brief, questions and display settings as one undo step. Cancel/Escape discards the draft; an unsaved draft recovers after reload from sessionStorage. Empty questions can be saved as drafts, and shorter sets are allowed. Ready content has a title, question, answer and valid format-specific content. Teaching metadata is optional. Invalid maths blocks Apply with a clear message. The native dialog keeps focus inside; nested equation editing remains available.

**Depth card** is always a standalone full-slide question and answer, with no side-by-side stepper, writing space or visualiser. Show answer flips to a full-width answer face with choices, feedback, diagrams and reasoning; Back to question restores the characters and prompt. A single card has no redundant question-sequence navigation. The editor offers no layout selector for Depth. Older saved workspace flags are ignored in the player and normalized to full/visualiser-off on edit/export without replacing content. The separate picker offers: tool, level, search, Preview card and Use this card. Its initial tool is the deck’s tool. Existing cards keep their claims, options, worked-error lines, explanations and diagrams. The tool-page Depth mode remains available. Ordinary practice does not load the Depth library. <!-- R43 -->

### Planning and authoring a set

A slide brief is optional: one or two sentences on what the slide’s questions test, or the key skill. When planning a lesson, write one for each question slide before authoring its questions (slides without questions need none); Harry’s own briefs and constraints take precedence. Store fixed questions directly with their slide. The classroom display omits the brief. <!-- R43 -->

Author at least five distinct fixed questions per skill-practice slide by default, deliberately varying the permitted operands and structures. Include correct answers and worked solutions. Diagnostics and exit tickets can stay short. Optional misconception guidance has example-specific incorrect responses; verify those differ from the correct answer. Teachers can save drafts or choose shorter sets without a hard minimum. <!-- R42 -->

Solutions match the referenced generator’s method, labels, notation, ordering and reveal boundaries, including its Original step where present. Inspect actual generator working before authoring. Estimation’s fixed sets and generator use `src/shared/estimationWorking.ts` for canonical Original/Round/Calculate assembly; authored fractions also retain the Numerator reveal and parentheses. Each canonical step becomes one reveal, followed by the separate final answer. User-written working stays editable. <!-- R42 -->

The Estimation deck (44 slides, Year 9, built from `specs/decks/estimation-y9.md`) is the pattern for a built deck: four sections (rounding to 1 s.f., whole numbers, fractions, decimals) with a divider at each pick-up point; each section runs a worked board, a five-question authored set and a generator slide; seven new Depth cards sit where they are needed. Write it for question slides when planning, before choosing content; most other slides need none. <!-- R43 -->

## Automatic text sizing

Text boxes and grids fit their text to their box. A text element's `size` is the **most** it will be: the slide shrinks the text (never below 20 units) until it fits, so a long prompt no longer needs a hand-picked smaller size. A grid (`quickfire`, retrieval, exit ticket) starts at 110 and shrinks until every box fits, whatever `size` it was saved with. Setting a size by hand in the editor (the size box or the toolbar) sets `fixed`, and the element is then drawn at exactly that size and the checker reports a text that does not fit; **Auto size** in the panel turns fitting back on. The content check only reports a text box that cannot fit even at the minimum (26). Do not add per-slide shrink helpers to a build script. <!-- ref -->
