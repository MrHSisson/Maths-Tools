# Faster builds, smaller merges and a steadier deck workflow
- **Status:** done
- **Updated:** 2026-11-21

## Intention
The repo is big enough that the way work is built, tested and merged slowed everything down. Planned at Harry's request on 2026-11-20 after four problems came together:
1. **Every merge ran every test.** About 7 minutes of tests (10 to 17 minutes of CI), run three times per merge, even for a docs-only change; nearly all of it Decision Maths.
2. **Branches lived too long.** Several chats and Codex work at once, merging was left to the end of a huge edit, and the same few files (patch notes, generated JSON, registry, tasks) conflicted every time.
3. **Decks depended on the merge order.** The live deck service checked decks with the code on `main`, so deck content waited for a code merge, and pushing a deck needed the Auto mode switch.
4. **Decks vanished from the Decks page.** The device's storage (about 5 MB) was full, so downloaded decks were never saved, yet "Check for changes" said "Updated".

**Measured**
- **Test time:** the full suite was about 965 s of work (6 to 7 minutes on the clock, 19 minutes on a GitHub runner); now about 590 s (about 4 minutes locally). The Critical Path generator, the main cost, builds valid Level 3 networks by design: 480 ms to 27 ms a question (Shorten 5.3 s to 0.4 s), every acceptance rule unchanged, the distribution of questions compared before and after.
- **CI on GitHub:** a full run takes 3.6 to 5.3 minutes (10 to 17 before). A change that is not "run everything" (docs, a deck, one tool, one Decision topic) runs a fraction of that; estimated test work per change on a laptop: docs 4 s, decks 32 s, one maths tool 108 s, mechanics 73 s, Critical Path 238 s, Network Flows 353 s, the Decision shell itself 536 s, shared code everything. Path filtering, the balanced runners and the browser cache were built after the last full run on GitHub that was timed; the first pull request after the merge should be read for them.

**Built (the letters are the original plan's steps)**
- **Tests and CI (A1 to A6):** ten test areas with path rules (`scripts/testAreas.mjs`: Critical Path, Network Flows, graphs, mechanics, Decision shell, cross-tool checks, per-tool tests, decks, CS, docs); only the areas a change touches run, `main` is compared with the previous commit, a nightly and a manual run run everything; the four runners are balanced by recorded time (`scripts/testShards.mjs`, `scripts/testTimes.json`, `npm run test:times`); the checks that loop over every tool run for only the changed tools (`TOOL_FILES`, `src/tests/toolFilter.ts`; a Decision topic's shared files map to their tools); the smoke job caches the browser; the Network Flows layout tests and `levellingMethod` are split into several files; a closed hole (a `FurtherMechanics` change used to skip its own tests) and one found on the way (the graph topics use two flow files).
- **Merge flow (B1, B2, B4):** the small-chunk rule and the parallel-session rule in `AGENTS.md`; patch notes are one file per session in `docs/patch-notes/` (`docs/PATCH_NOTES.md` is generated); generated files get a git merge rule set by `npm install`. **B3 decided:** no auto-merge and no merge queue; Harry decides each merge and the session says when a branch is ready.
- **Decks (C1 to C5):** the stale deck-preview task corrected; a full device frees space and says "Storage full"; decks are listed from a small shared summary and fetched when opened, the device keeps the 8 most recently used and never drops unsent work; the deck server keeps a question that needs newer code (a new question format or rectilinear shape or version), refuses anything else malformed and refuses to publish such a deck, and the site shows "This needs a newer version of the site" for it; the unused shared question library was removed; `.claude/settings.json` allows the routine deck commands. **C6 decided not needed:** the tolerant server plus the branch preview (same storage) shows new deck content before its code is merged on production.
- **Tokens and checks (D1, D2, E1, E3):** the cost of a long session is the conversation re-read each turn, so no code-graph tool (D3 not done); `CLAUDE.md` 40 KB to 30 KB and the decks reference split into four topic files; 12 Solving Trig Equations questions solved independently in Wolfram, all matched; the Education Skills plugin stays on.
- **Flaky generators:** under 1 in 100, draw again (built into `makeUniqueQ`; Ratio Manipulation's fall-backs are marked `_fallback`); 1 in 100 or more, an authored fall-back; failing most of the time, a 100+ authored set or a generator built to pass. Measured all of Ratio Manipulation: only Level 2 "1 : n / n : 1" falls back (about 1 in 10,000), so no bank is needed. `src/tests/fallbackRates.test.ts` measures. The 1-in-1,000 to 1-in-100 band is Harry's call each time.
- **Not done, on purpose:** a separate mechanics or Critical Path shell (no saving beyond the area split, a large refactor); an authored-bank mechanism (nothing needs it yet).
- **Also fixed along the way:** the dashboard read only `###` patch-note headings (now every entry); README and `CLAUDE.md` describe the new CI; a flaky Ratio Manipulation test is seeded.
