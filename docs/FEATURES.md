# What each feature is

Every feature a tool can have, and what it is for. To see which tools have each one, use the Matrix view on the Tools page, or Developments → Feature tracker.

## Modes — the tabs across the top of a tool

### Whiteboard
**For:** teaching from the front of the room. One question at a time, big, with a blank working space beside it (or the visualiser camera). **How it works:** New Question, Show Answer, text-size chevrons, fullscreen. **Where:** every tool.

### Worked Example
**For:** showing how the answer is built, one mark at a time, so the class has thinking time. **How it works:** the step-by-step cascade reveals the working a line at a time (earlier steps stay on screen, dimmed); each line can itself build up in parts, in the order a teacher would write it on the board. Show All puts the whole working up at once. **Where:** every ToolShell tool.

### Worksheet
**For:** a printable or on-screen set of practice questions. **How it works:** choose how many questions and columns, then Generate. Answers can be shown for the whole sheet or one cell at a time (double-tap a cell). Fullscreen fits the sheet to the screen. **Settings:** borders, Smart Progressor, say the prompt once, condensed wording. **Where:** every ToolShell tool.

### Differentiated worksheet
**For:** one sheet with a column per level so a mixed-attainment class each gets their own. **How it works:** pick the levels; each column uses that level's own Question Options. **Where:** Worksheet mode, every ToolShell tool with more than one level.

### Depth
**For:** going beyond generated practice: hand-written questions that find misconceptions, make students explain, and stretch the secure. **How it works:** the teacher dips in by purpose (diagnose, explain, extend) and level, in whatever order the class needs. Each item is a question slide then an answer slide, with cartoon speakers, lettered options that name the misconception behind each wrong choice, and Feathers the owl as a quiet mascot at the left (he does not speak). The question never moves when the answer is shown: the right option is ticked in place and the answer fades into a gap reserved below. A "Start here" quick check gives one question per level. Items grey out when the Question Options needed for them are off. **Where:** the tools that have a question bank (see the Matrix).

### Teach deck
**For:** the teaching part of a lesson, as slides pressed through one beat at a time before moving to practice. **How it works:** hand-written, misconception-driven slides with animated pictures (split bars, factor trees, index tiles). **Status:** Developing-tools mode only for now. **Where:** the tools with a deck (see the Matrix).

### Lessons
**For:** a teacher's sequence inside one tool: for example a Depth check, a Whiteboard practice, a Worksheet to set, then an extension. **How it works:** the burger menu's Lessons page shows a card per lesson; each step opens a pre-set mode, level and options, and a step bar keeps the place. **Status:** Developing-tools mode only for now.

### Decks (whole lessons)

**For:** teaching a whole lesson from one place, on the projector, without jumping between tool pages, and shaping it to how you teach. **How it works:** a deck is a planned run of slides (objective, vocabulary, boards to write on, targeted practice questions, Depth checks, discussions, quickfire grids, exit tickets). A board has a control in the top bar of the player to show it filled in, structure only or blank (B cycles the modes); the central **Skill practice** editor opens directly on the slide’s own questions. An optional **slide brief** says what the questions should test; it can be copied into chat. Claude writes one for each question slide when planning lessons, or follows the teacher’s. The question editor shows the list of questions, the selected question’s fields and a live preview side by side; **Add question** adds to the set. **Depth card** has its own picker; **Edit card** (double-click it) makes this deck's own copy so its wording, options and answer can be tweaked, and from a tool's Depth section **Edit in a deck** (Developing-tools mode) adds an editable copy to a deck. The bank is never changed, and a copy you have edited stays yours. Depth card also has its own picker and retains the original character avatars and speech bubbles; Feathers is a mascot only, with no quotes and no teacher notes. Applying the brief and questions is one undo step. The player offers previous/next questions and a clear end of sequence. **Show working** slides the question to the right while the numbered solution unfolds on the left, with previous/next steps, Show All and a final green answer marker. Authored solutions follow the matching generator’s method, labels and reveal steps. Generator slides use the same layout. Fixed question sets and live generators share four editor-selected layouts: Full-width, Full-width flipped, Workspace right and Workspace left. Full-width shows every working step (steps on the left, question on the right; when the working has a ratio table or bar model, the question sits above the steps and the picture develops on the right), and flipped is its mirror. The workspace layouts keep room for writing and reveal only the answer. Depth cards remain standalone full-slide questions and answers, with no split stepper or workspace layout. The writing/camera panel stays in place for ordinary question sets, including across their questions. Camera controls are tucked into Workspace options. Reduced margins and panel padding give the content more room. Slides and writing spaces are plain white. Generated practice is a separate activity. **Worksheets** can be pinned to a lesson (up to three): each prints on an A5 page with the tool pages' Worksheet layout, with an answer sheet that has the same boxes as the questions (the answer in each box), from File → Worksheets, and the lesson's Worksheet slide shows the answers on a click. The player and the editor fit the screen you can actually see, so on a tablet the browser's address bar no longer pushes the bottom of the slide off. In the editor the slide can be zoomed in or out (two-finger pinch, Ctrl + scroll or the buttons) to write in a small box with the Pen, and panned with two fingers. A **timer** of 1 to 10 minutes can be called on any slide in the player (the clock button, or T): a line along the bottom of the slide shrinks as time runs out, with the time and a pause button. A slide can also carry its own timer, set in the editor, which appears and starts as the slide does. The **Starter** layout is four numbered boxes in a 2 × 2 grid. The editor has a **Pen**: write or draw on a slide with a mouse, finger or stylus (colours, thickness, rub out, clear, undo) and it is saved with the slide. With a stylus, a resting hand is ignored (**palm rejection**: large contacts, and touches while the stylus is touching or hovering, do nothing), so it never box-selects or pans the slide. In the player the pen's writing now stays with each slide while the deck is open, so you can go back to a slide and find your writing there. Harry and Claude can edit the same deck: saves from either are merged by slide and element instead of overwriting each other (Harry's version wins if both changed the very same thing), and an open editor looks for changes made elsewhere only when asked (File → Check for changes for that deck; the deck list has a Check for changes button for all decks), so it does not keep the database awake; a save is always merged by the server. The **Number grid** (1 to 100) is a slide piece for the sieve of Eratosthenes: tap numbers to scribble them in a prime's colour, finish that prime's times table in one click, or show the finished sieve a click at a time; **Print grids** gives two blank grids per A4. The **Ratio table** and **Bar model** pieces are the site's own pictures on a slide: Filled in, Structure only or Blank (the board control), or built up one row, or one part and brace, per click. Parts of a slide can appear one click at a time (a discussion shows its prompt, then the key point, then the question, then the answer). **Full screen** hides every control so the slide fills the screen (a small control pill appears when the mouse moves and fades away again; Esc leaves). The bottom bar is the same on every slide: Back, progress and count, Next. The ink pen works on every slide and clears when the slide changes. In the editor, **layout warnings** flag text that spills out of its box, runs off the slide or overlaps other text (an amber button by the zoom controls lists them; click one to select it). **Edit** opens the slide editor, with a menu bar (File, Edit, Insert, Slide, View) and a toolbar whose quick controls follow what is selected (text size with an **Auto** fit that you can override by pressing bigger or smaller, on every piece of text, equation, board, question set, generator and book activity; bold, alignment and colour; Arrange; duplicate and delete): type straight onto the slide, write maths in the equation editor (fractions and powers typed as they look), add shapes, arrows, pictures, boards, questions and Depth items, and line things up with guides. Changes are saved as you go and shared with your other devices. **Configure generator** opens a central popup with the tool’s tabs, levels, Question Options and a preview; Apply saves the setup in one undo step, while Cancel discards it. Any tool's generator can run on a slide like its Whiteboard (New question, working step by step), or fill a book activity with a numbered set of questions to copy into books. From a tool page, **Send to a deck** turns the current setup, or the question on screen, into a deck slide. The **Slide library** shows every layout. Open a deck from the tool's burger menu or the Decks page. **Status:** the editor is behind the admin password. **Publish this deck** (File menu) makes a frozen read-only copy that anyone can play; published decks are listed on the **Decks page** (a "Decks" button in the landing page header, `/deck-gallery`) as cards showing their first slide, grouped under a heading per strand (Number, Algebra, Ratio & Proportion, Geometry, Probability & Statistics; set under About the deck in the editor), and the deck editor's list shows every deck the same way with an edit button (with Developing tools on, the Decks page also shows the unpublished ones, tagged), with a **Deck editor** button that asks for the password. Each question slide carries a small label: **Deliberate practice** for written questions (they have no levels: a written set is a ladder of steps, agreed in the plan), **General practice · Level n** for a generator. Estimation is the first deck. **On a phone, a deck is only previewed:** there is no Deck editor button, no Edit, and the editor addresses go back to the Decks page. Opening a deck shows a start card; one tap starts the show full screen, asks the phone for landscape (an upright iPhone shows the slides turned on their side instead, so turning the phone reads them upright), and you swipe from right to left for the next slide and from left to right to go back. The controls bar fades after a few seconds; tap the slide to bring it back, and tap again to hide it. The **Venn diagram** piece is a box with two circles and cards (words, numbers or prime tiles) that the class drags to where they go and that stay where dropped, with no checking; cards can come in one per click, followed by the HCF and LCM lines.

Deck grids and book activities reveal an individual answer with a 500 ms hold within 8 px.

### Decks by class (finding a deck by who it is for)

**For:** finding a lesson by the class you are teaching, now that there are a lot of decks. **How it works:** once signed in, the Decks page opens on **By class** and also has **By topic** (the strands and topics); signed out there is only the published list. By class lists a heading per year (7, 8, 9, 10, 11, A-Level) with its classes as buttons (7M1; 9M6, 9M3, 9M2; 12FM, 13MA, 13FM), each with how many decks it has. Click a class and its decks appear as the usual preview cards, most recently made first from the left. Only that class's decks are loaded, when you click it. A deck can be in more than one class (it is not copied). **Add a deck…** puts a deck in the class, and the cross on a card takes it out (neither is offered on a phone). The years and classes are folders, and folders inside folders are coming next.

### Deck strands and topics (filing the Decks page)

**For:** keeping the Decks page in the order and under the headings you want, instead of five fixed names. **How it works:** decks are filed under a strand (Number ... Probability & Statistics, A-Level with Maths and Further Maths inside it, Starters; you can change all of these) and, if you want, a topic inside it (Factors & multiples inside Number). You make, rename, reorder, move and delete them yourself with **Manage categories** on the Decks page (it appears once Developing tools is on), and file a deck by **dragging its card onto a heading**. On a touch screen, where dragging does not work, open the card's (i) and use **Filed under**; the same menu is in the deck editor's About the deck. A deck sits in one place; empty headings show only to you (with a hint) and anyone else sees just the strands and topics that have published decks, in your order. Each deck can also carry a **lesson pitch** (Upper, Middle or Lower band), set in the editor's About the deck and shown only in the card's (i). Decks not filed appear under **Not filed** (**Other decks** to everyone else).

### Decks on this device and the shared copy

**For:** a Decks page that always opens quickly and never silently loses a deck. **How it works:** the Decks page lists every deck from a small shared summary (title, where it is filed, its first slide, how many slides); a deck is downloaded only when you open it, and the device keeps just the few decks you opened or saved most recently, never dropping one with changes that have not been sent. **Check for changes** refreshes the decks this device holds. If the device's storage is full it frees space from old saved versions first, and if a deck still cannot be kept it says **Storage full** and names the deck, instead of "Updated".

### Content that needs a newer version of the site

**For:** building deck content before the code that draws it is live, and seeing it on a branch preview. **How it works:** the shared deck service keeps a question that uses something only newer code understands (a new question format, a later rectilinear shape) and says what it kept; the live site then shows "This needs a newer version of the site; it will appear once its code is merged" in that place, while the rest of the slide still works. A deck holding such content cannot be published until the code is merged.

### Inverse graph animation (decks)

**For:** showing where the graph of an inverse function comes from. **How it works:** a slide piece that animates y = sin x (restricted to −π/2 ≤ x ≤ π/2), y = cos x (0 ≤ x ≤ π) or y = tan x (−π/2 < x < π/2) being reflected in the line y = x and then separating into its own axes as arcsin, arccos or arctan, one click at a time (restrict, mirror line, fold, separate). Back plays it in reverse.

### Rectilinear shapes in decks
**For:** teaching area by splitting into rectangles and by removing cut-outs. **How it works:** live generator slides show the tool's own diagrams and step highlighting. Authored questions have chosen dimensions, orientation and method (shapes: L, T, three- and four-step staircases with steps of different sizes, cross, capital I, U, N, comb, frame; at 270° corners one length of each pair can be drawn inside the shape so labels do not crowd); L-shapes can deliberately mark a length to find by addition or subtraction before area. Board edge labels are larger while worksheet labels keep their print size. Reduced labelling defaults on. Make printable worksheet saves an independent set with a supplied split and prompts, a split only, or independent working space; questions and worked answers print from File → Worksheets, on A4 pages built to be shrunk two to a sheet (large pictures, one page per kind of question, the first question of each page laid out as numbered steps). **Where:** deck editor, Perimeter & Area → Rectilinear Shapes.

### Print slides (decks)
**For:** sticking key slides into books, or handing out a whole lesson's slides. **How it works:** File → **Print slides…** in the editor, or **Print slides** in the player, lists every slide with a tick box; **All slides**, **Key points** (the teach and key language slides) or **None** set them quickly. Choose 1, 2, 4 or 8 to a sheet of A4 (8 is two columns by four rows; 2 stacks two portrait; 4 and 1 turn the page landscape so the slides fill it), with **Copies of each slide** (1 to 8, to print the same slide repeatedly), faint dashed **Cut lines** between slides (each slide centred in an equal part of the sheet, so a sheet cuts into identical pieces) an optional thin border, and **Fill to edges** (slides pushed to the outside of the sheet, with the spare paper at the cut instead). The slides print exactly as they look on screen, with answers hidden.

### Printables
**For:** ready-made sheets with no generated questions, for the class to fill in: blank number lines, place value tables, binary tables, ratio tables and coordinate grids. **How it works:** a "Printables" heading in the burger menu lists the sheets a tool offers; one click opens the A4 page ready to print. **Where:** only tools whose working is built on a blank the student fills in (a number line, place value table, ratio table or graph); the dashboard's Printables filter lists them.

### Print sheets and saved questions
**For:** choosing the questions you want to teach or print. **How it works:** generate and inspect one question at a time, then press the pin beside New Question to save that exact question. The saved-question panel's **Print saved questions (n)…** prints your chosen questions, answers or both. The Decision and Further Mechanics tools have no Worksheet mode or batch generator: only questions you deliberately save enter the basket. Named lists and **Copy basket link** preserve the selected recipes; **Reload** restores a question and the toolbar's `‹ n / N ›` steps through your selections. **Where:** all Critical Path skill tabs have A4 layouts: networks to fill, blank precedence tables, ruled working areas, Gantt/worker allocation axes, histograms or levelling charts as appropriate. Gantt Levels 1–3 preserve given bars and chart options; Level 2 leaves network times for the passes. Missing values remain x, and allocation grids do not reveal the minimum team size. Answer sheets complete the diagrams or give model answers. Saved exam questions in Critical Path, Network Flows and Dimensional Analysis print as papers with mark schemes; saved Dimensional Analysis skills print with working space and an answers page. A saved recipe records the tool, level, options and seed, and warns if a later generator change makes it rebuild differently.

## Controls — what a teacher can change

**Decision Question Options:** each sub-tool and level shows its own relevant choices and remembers its own selections during the visit. Switching levels starts with that level’s defaults, then restores its previous selections on return. Course/practice selectors remain shared. Larger menus use the same Questions, Numbers, Method and Display tabs as normal tools on laptop, tablet and phone. Old links and saved questions are checked against the current level’s choices. This also covers Dimensional Analysis.

### Levels
**For:** moving the same question type from easy to harder. **How it works:** Level 1, 2 and 3 buttons above the question. A tool can offer fewer than three; the buttons it does not use are hidden. An (i) beside the buttons (on a phone, beside the Difficulty title) says what each level means; tapping a level opens a fuller pop-up with what can be chosen there and a button to switch to it. **Where:** every ToolShell tool, and the Decision tools.

Small Critical Path networks can include three parallel activities and three immediate predecessors. Delay and Glyn explanation questions vary their outcomes, with matching worked answers and mark schemes.

Critical Path’s Delays and changes levels differ by the change being considered: delay against float; shorten a critical activity; up-to delays or removal. Every level offers Small (6–7 activities) and Medium (8–9 activities) networks independently, defaulting to Medium.

### Question Options
**For:** tuning exactly what kind of questions come up (which question types, what sort of numbers, how the answer must be shown). **How it works:** a popover of buttons grouped into pools; ticking more than one in a pool mixes them. Every option sits under one of four names, always in this order: Questions, Numbers, Method, Display. A level with more than eight choices shows them as small tabs at the top of the popover, so a few groups show at a time; a smaller one just lists its groups in that order. A label ending in an asterisk is beyond standard questioning and is off by default. Some options grey out until another option they depend on is on. Every option says in a sentence what it is for (hover its (i) on a laptop; on the Decision tools the sentence shows beside the option's heading, or under it on a phone or tablet), and the headings use one wording across the site: Title Case, one word per idea ("Method" is how it is worked, "Working Shown" is how much working, "Answer Format" is how the answer is written, "Ask for" is what the question asks for). **Where:** every tool.

### About this tool
**For:** telling the teacher in plain words what the tool is for. **How it works:** opened from the burger menu ("About this tool"); it says what the whole tool is for, then lists each sub-tool with its purpose; a sub-tool opens to show what each of its levels means and what its Question Options do (each one explained in a sentence, such as what 'Extended Range' extends; the same note appears when you hover an option's ⓘ). The level text is the same as in the level (i), which gives the quick version for the tab you are on. It does not explain the modes. It opens by itself the first time a live tool is used on a device (never from a shared link or a lesson step) and then stays out of the way; "Show tool tips again" on the landing page menu brings that back. On a phone it is a full-screen sheet. **Where:** every ToolShell, Decision and Computer Science tool, the word games, the Visualiser and the Parallel Lines Explorer (these last ones keep hand-written notes). Each ToolShell tool also has a level (i) beside the level buttons: it says what Level 1, 2 and 3 mean, and tapping a level opens a fuller pop-up with what can be chosen at that level and a button to switch to it.

### Sub-tool tabs
**For:** several related question types in one tool (for example Elimination and Substitution). **How it works:** small tabs under the title; a tool with only one sub-tool shows none. **Where:** most ToolShell tools.

### Share link (Copy Link to Setup)
**For:** sending a colleague or a class the exact setup: mode, level, options, question count. **How it works:** the address bar always holds the current setup; the burger menu copies it. A worksheet link generates the sheet on arrival. Old links never break, and when a tool's address changes the old address still opens it (Times Tables moved from `/timestables` to `/times-tables`). **Where:** every ToolShell tool.

### Saved lists and recent questions
**For:** going back to a question the class has moved on from, and keeping the questions for a lesson together across tools. **How it works:** the pin button beside New Question **saves** the question on screen to the open list; the small arrow joined to it opens one panel. At the top, a list picker with **New list**, **Rename** and **Delete** (a list such as "Year 10 Tuesday" is named by you; the last list cannot be deleted, and the first is called Saved); then Save, **Print saved questions** (Decision tools), the open list's questions (up to 30 per list) and the last five **Recent** questions. A list can mix tools: a question from another tool shows with its tool's name, and picking it takes you to that tool with the question back exactly as it was (tool, level and options too). Saved lists are kept on this device, so they are still there after the page reloads or closes (a question is stored as a recipe, not a copy, so one the tool can no longer draw the same way says so when it comes back). Recent is memory only: gone when the page reloads. The burger menu shows the same lists. **Where:** both shells; hidden in Worksheet mode.

### Subjects and strands on the landing page
**For:** finding a tool by subject. **How it works:** three tabs, GCSE Maths, A-Level and Computer Science, each listing its strands in order of the scheme of work. Computer Science holds the revision topics ("Computer systems") and the binary and number-base generators ("Binary & number bases") together. The Classroom strand (the Visualiser) shows under every tab; internal pages sit in a Workshop strand that appears only in Developing-tools mode. **Where:** landing page.

### Decision Maths hub (by specification code)
**For:** finding a Decision generator by the part of the AQA 7367 Discrete specification it covers. **How it works:** the A-Level tab shows one **Decision Maths** card instead of one card per tool, under a **Further Maths** heading beside the Further Mechanics card. It opens a page of the chapters DA to DG ; opening a chapter shows an **Exam-style questions** card at the top, an **Open <tool>** button, then the whole course's specification statements in the spec's order, with anything beyond AS marked **A2** (an A2-only statement carries the tag; a statement with an A2 extension shows "A2 adds …" and an "A2 practice" row; AS content needs no label, since the A-level course covers it too), each followed by the generator **sub-tools that practise it** (for Critical Path, for example, DE2 lists Forward pass, Backward pass and Missing time); each opens the tool on that sub-tool. Practice that goes beyond AS sits on its own "A2 practice" row under the statement it extends. A chapter with nothing built says so, and a chapter whose generators are not live yet says "Coming soon". Each chapter has an address of its own (`/decision-overview#DB`), and `/decision` goes to the page. Everyone sees the live generators; Developing-tools mode also shows tools still in development, each statement's link back to the older AQA D1 and D2 papers, the question banks and the older-papers page (the explanatory (i) notes on each statement and the list of particular kinds of exam question were removed from the hub pages on 2026-11-21). The tools keep their own addresses and are still found by the landing page's search box. **Where:** landing page (A-Level), Decision Maths.

Decision and Further Mechanics chapter cards keep the specification statement count and generator status on separate lines, including at narrow widths and enlarged text sizes.

### Further Mechanics hub: planned sub-tools
**For:** showing a teacher what is coming. **How it works:** under each specification statement of the chapters not yet built, the sub-tools planned for it appear as greyed-out buttons that do not open anything; a statement with an A2 layer shows it in brackets after the statement. **Where:** Further Mechanics hub, chapters MB to ME.

### Dimensional Analysis (Further Mechanics MA, in development)
**For:** practising dimensional analysis, the AQA 7367 / 7366 topic MA1 and MA2, one micro-skill at a time and then as exam questions. **How it works:** three skill tools, each with Question Options so one tool gives many kinds of question: **Find the dimensions** (a quantity from its name or its units, an expression, or a constant in a formula; written or circled), **Check consistency** (show a formula is consistent, find the odd term out, find a missing power, or circle the consistent formula) and **Find the powers** (equate the powers of M, L and T and solve; in letters with no context, with named quantities, or in a worded situation such as a pendulum or an orbit; including "show one power is zero" and "show it cannot work"). **Exam style** switches to short chains of lettered parts with marks and an AQA-style mark scheme, from the same generators, with hand-selected basket printing of the paper then mark scheme. Everything is written as an examiner expects: the powers are α, β, γ, all maths is typeset, and the working is the formal chain with square brackets, for example [F] = [ma] = [m][a] = M × LT⁻² = MLT⁻². The picture is **the page a student would write**: it has a title ("Find the dimensions of force"), opens with a short given set (length, time, mass, speed, acceleration), builds every other quantity from those, stating the formula first (F = ma, kinetic energy ½mv²), and writes it out in full with square brackets: [F] = [ma] = [m][a] = M × LT⁻², with a power on a bracket written as [v]² and then expanded. A division is kept as a fraction and cancelled, and only the last line uses negative powers (MLT⁻²/L = M/T² = MT⁻²). Beside it a teacher talks you through each line in words. The page never scrolls. A built quantity is one step that opens into its parts with a chevron (a Builds option shows every step); dimensionless numbers and trig functions are stated (\[½\] = 1); angle, sin, cos and tan are questions. On a phone the whole solution is one open scrolling page. Save individual skill or exam questions with the pin, then print the basket with working space and answers or mark schemes. There is no Worksheet option or random batch generator. **Where:** `/dimensional-analysis`, Further Mechanics hub.

### Work, Energy, Power and Elastic Strings (Further Mechanics MC)
**For:** practising the work, energy and power chapter of the AQA 7367 / 7366 mechanics option one skill at a time: work done (force and distance, gravity, a force at an angle, several forces, a variable force) and energy (kinetic and potential energy, the work-energy principle, conservation of energy). **How it works:** each question is a particle or a worded situation, with a mechanics diagram, the written working a line at a time (the newest line in blue) and the answer to 3 significant figures; the Course option hides the A2 content (cos θ, slopes by angle, velocity vectors) at AS, and the Diagram option gives the picture with the question, builds it up as the working goes on, or leaves it out. **Working Picture (Energy and Elastic):** an option swaps the diagram for energy bars, one column for the start and one for the end, each stacked from gravitational, elastic and kinetic energy and work, so the two columns are the same height; the bars appear once the energy equation is written. **Printing:** save a question with the pin and print it from the saved-questions list: the diagram sits under the question with a working box, and the answers page carries the worked solution. **Still in development banner:** the four tools, the MC chapter on the hub and the flashcards open to everyone but show an amber "Still in development" notice on opening (it can be closed for the rest of the visit), so it is known they are not in their final form. **Where:** the Further Mechanics hub (open to everyone since 2026-11-23).
**Power (MC7):** four sub-tools: Average Power (lifting, braking, a pump, accelerating at constant power), Force and Speed (P = Fv, constant speed, F = ma, a resistance kv or kv²), Power on a Slope (A2: steady speeds up and down, the angle, the time from rest, drawn with a force diagram with the weight resolved) and Power from Motion Data (a displacement function s(t) or a speed-time graph). Same options and working as Work Done and Energy. Force and Speed also has a train of an engine and coaches (the acceleration, then the tension in the coupling) and, at A2, the work and power from a vector force and displacement. **Where:** `/power`, Further Mechanics hub.
**Elastic Strings and Springs (MC4, MC6):** three sub-tools: Hooke's Law (tension or thrust from a length or extension, the extension, k or the modulus, a mass hanging in equilibrium, a particle between two vertical strings), Elastic Potential Energy (the energy stored, the work between two lengths, the modulus or length from the energy) and Elastic Energy Problems (release on a smooth table, a particle dropped on a string: greatest extension, acceleration at the lowest point, greatest speed; at A2 a rough table and a smooth slope; a Show That switch). Hooke's Law also has, at A2, a particle on two strings fixed at two points (the triangle, then resolving). Same options and working as the others; lengths can be given in centimetres. **Where:** `/elastic-strings`, Further Mechanics hub.

### Mechanics diagrams
**For:** one drawing system for every mechanics question: a body on level ground, a slope, a vertical fall, a pulley, a spring or string, a force-displacement graph, energy bars. **How it works:** a picture is made of parts (the setting, the forces, the measurements) that can be shown at once or added one at a time as the working goes on; labels are placed by one solver and shrink a little rather than collide. **Where:** inside the Further Mechanics tools (`src/shared/mechanics`).

### Flashcards (Further Maths)
**For:** learning the key formulas, definitions, what a situation implies, and the common mistakes of a Further Maths topic, and a quick check of what a student remembers. **How it works:** choose a topic (the statements, AS or AS and A2), then one of four decks: **Formulas**, **Definitions**, **Implications** (what a situation tells you: maximum speed implies zero acceleration and zero resultant force) or **Common mistakes**, or a mix. Each deck shows its size and a coloured bar of where the student stands. The card turns over; the student says Not yet or Got it. Every card is in one of three piles (learning, getting there, secure): Not yet sends it back to the first, Got it moves it up, and a secure card comes back after a week. Fronts are always a clear prompt ("State…", "Define…", "What does this imply?"). Formula and definition cards can also be asked back to front, and some cards carry a mechanics diagram. The piles are kept on the student's own device and nowhere else. **Where:** Further Mechanics hub, under Revision; Work, Energy and Power (MC1 to MC7) so far. **Plan:** `specs/flashcards/further-mechanics-mc.md`.

### View as (Auto · Mobile · Tablet · Desktop)
**For:** previewing the phone or tablet layout, or fixing a device that guesses wrong. **How it works:** a landing-page menu setting, stored per device, that every shell obeys. **Where:** landing page burger menu.

### Swap sides (question left or right)
**For:** putting the question on whichever side suits the room, or the teacher's reach. **How it works:** mirrors every two-sided layout at once: the Whiteboard's question and working box (embedded and fullscreen, including the draggable divider) and the Worked Example's steps and picture. Kept per device. **Where:** the landing-page burger menu ("Two-sided layouts"), each tool's burger menu ("Swap Sides"), and a button on the fullscreen bars. The Decision tools are not yet included.

### Ink pen (draw anywhere)
**For:** writing on top of any tool page, on a touch screen or interactive whiteboard. **How it works:** a pencil button opens a movable bar with Freeze, Pen, Eraser, Undo, Clear and colours. Ink stays until you change page. **Where:** every tool page on a tablet, laptop or whiteboard, not the landing page and not on a phone (the real device, or View as: Mobile).

Ink gestures that start on controls pass through without dots, even beside recent writing; continuous strokes can cross controls without breaking.

### Fullscreen and the collapsible working panel
**For:** filling the screen for a whole-class view. **How it works:** Fullscreen enlarges the question; the working or visualiser panel on the right can be collapsed so a large diagram fills the width, and re-opened from a button in the question box. **Where:** Whiteboard.

### Visualiser camera
**For:** showing a student's paper or a hand-drawn working alongside the question. **How it works:** the working panel can show the live camera. **Where:** Whiteboard, the Visualiser tool and question deck slides with a workspace. On a deck slide the camera is explicitly started, can be switched or stopped, and is released when leaving the slide.

### Working scaffold
**For:** a model for the students to copy while they work, such as a place value table. **How it works:** drawn in the working box or beside the question, with a button to hide it once students no longer need it. **Where:** the tools that have one (see the Matrix).

### Staged reveal
**For:** letting the class attempt part of the task before the answer, such as plotting a number before the answer line appears. **How it works:** an extra button in the question box (for example "Show Plot") reveals the in-between picture; Show Answer still shows everything. **Where:** Rounding.

## On the worksheet — how a sheet is built

### Calibrated worksheet (Smart Progressor)
**For:** putting a worksheet in order from easy to hard by how hard each question really is, not by which option made it. **How it works:** each question is scored from its own numbers and working; a sample of thousands cuts the scores into eight bands, and the sheet draws evenly from the bands the ticked options can reach, easy first. A **Smart Progressor** switch in Worksheet Settings turns it off. A few variety pools (the zero kinds in Rounding, Speed / Distance / Time in a mix) are also kept roughly even on a short sheet by the same switch. **Where:** every tool with the Calibrated mark on the dashboard.

### Say the prompt once
**For:** a cleaner sheet when every question starts with the same instruction ("Simplify:"). **How it works:** the shared wording is shown once above the sheet instead of in every cell. Printing still repeats it. A switch in Settings puts it back.

### Shape labels that avoid each other (and Reduced Labelling)
**For:** a shape picture where every length is easy to read and nothing sits on a line or on another label. **How it works:** each label tries a grid of spots beside its side (slid along it, pushed out, inside the shape or on the line when there is no room), scores each against the outline, the dashed helper lines, the other labels and the picture's edge, and takes the clearest; a thin dashed line joins it to its side. **Reduced Labelling** (a switch) leaves out only the labels the drawing already implies (a side equal to the one opposite it, a rectangle's other two sides), so nothing has to be worked out. Rectilinear staircase steps stay labelled even when their lengths happen to match; it pairs with Some Missing, whose ? sides are always found by adding or taking away. **Where:** Perimeter & Area.

### Condensed wording
**For:** fitting more questions on a sheet by shortening long wording. **How it works:** a switch in Worksheet Settings shows the question with a small tag ("(3 d.p.)") instead of the full sentence. Print and the whiteboard keep the full wording.

### Answers in place of the question
**For:** checking a sheet cell by cell. **How it works:** with answers on, each cell shows its answer instead of the question; double-tap a cell to flip just that one. The Whiteboard now does the same for text questions: Show Answer swaps the question for the answer in the same place, so nothing shrinks or jumps.

### Own print layout (diagram printing)
**For:** printing sheets of pictures (angles, number lines, grids) neatly, with the right number per page. **How it works:** diagrams are packed by their shape using the same page-fill engine as text sheets; more columns means smaller, denser diagrams. **Where:** the diagram tools.

## Behind the scenes — what makes a question good

### Instant reformat
**For:** changing how a question is shown without changing the question. **How it works:** when a display option is switched (decimal or fraction, say, or words in the column headings), the shell redraws the same maths in the new form instead of making a new question, so the class keeps the problem they were looking at. Every tool gets this for any option marked as display-only. **Where:** every tool, for its display options.

### No repeats in recent questions
**For:** a class never seeing the same question twice in a row, or again within a few clicks. **How it works:** New Question compares the new question's content with the last 15 shown and quietly makes another if it matches (the Decision tools check the last 8). It compares what is on screen as well as the maths itself, not a label, so two questions that look the same are caught, and when in doubt it asks for another question rather than letting a repeat through. Replaying a recent or pinned question, and share links, still show exactly what was saved. Worksheets use the same check across the whole sheet, so a sheet never repeats a question unless the tool cannot make enough different ones. **Where:** Whiteboard and Worked Example in every ToolShell tool, and the Decision tools.

### Drawing again when a question cannot be made

**For:** a worksheet never getting the wrong kind of question on the rare occasion a generator cannot make what you asked for. **How it works:** if a generator fails, or hands back its fixed fall-back question, the worksheet quietly asks it again (up to three more times) before using the fall-back. A question that fails less than about 1 time in 100 is handled this way; the measuring and the rule for anything that fails more often are in `AGENTS.md`.

### Changing options keeps your question
**For:** changing your mind without losing the question on screen. **How it works:** changing a Question Option no longer replaces the current question. The next question you ask for follows the new options. Only a change of level or sub-tool gives a new question straight away. **Where:** Whiteboard and Worked Example in every tool, and the Decision tools.

### Developing picture
**For:** a Worked Example where one picture is drawn up step by step beside the working (a place value table filling in, a graph being built, a diagram getting its angles). **How it works:** the picture updates in place as the steps advance instead of being reprinted each time. **Where:** the tools marked on the Matrix.

### Closing answer step
**For:** the working ending by stating the answer, so no separate answer box is needed. **How it works:** a tool whose last step already states the exact answer can switch the extra green answer box off.

### Representations (the eight pictures)
**For:** the same picture meaning the same thing wherever a student meets it. **How it works:** bar model, number line, area model, algebra tiles, negative counters, prime factor tiles, place value table and ratio table are the site's visual vocabulary; new pictures must start from one of them. The Matrix shows which tool uses which.

### Techniques engine
**For:** reusable blocks of worked-example steps (solving a linear equation, substituting back) so many tools explain the same move the same way. **Status:** built and used by a few tools; a Technique Library page shows them in Developing-tools mode.

### Skill links
**For:** a dotted-underline word in the working (for example "LCM") that would open a short slide lesson on that skill. **Status:** Developing-tools mode only: the markers are in three tools and show as plain text otherwise.

### Smoke tests
**For:** catching a broken question before a teacher meets it. **How it works:** every tool is run through 40 questions per tab and level; the tests fail on a crash, a repeated question key or any maths that will not draw. The Matrix shows which tools are covered.

### Spec
**For:** a written brief in `specs/` that says what a tool should teach, with sample questions that define "correct". The Matrix shows which tools have one.
