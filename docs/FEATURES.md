# What each feature is

Every feature a tool can have, and what it is for. To see which tools have each one, use the Matrix view on the Tools page, or Developments → Differs from the standard.

## Modes — the tabs across the top of a tool

### Whiteboard
**For:** teaching from the front of the room. One question at a time, big, with a blank working space beside it (or the visualiser camera). **How it works:** New Question, Show Answer, text-size chevrons, fullscreen. **Where:** every tool.

### Worked Example
**For:** showing how the answer is built, one mark at a time, so the class has thinking time. **How it works:** the step-by-step cascade reveals the working a line at a time (earlier steps stay on screen, dimmed); each line can itself build up in parts, in the order a teacher would write it on the board. Show All puts the whole working up at once. **Where:** every ToolShell tool.

### Worksheet
**For:** a printable or on-screen set of practice questions. **How it works:** choose how many questions and columns, then Generate. Answers can be shown for the whole sheet or one cell at a time (double-tap a cell). Fullscreen fits the sheet to the screen. **Settings:** borders, Smart Progressor, say the prompt once, condensed wording. **Where:** every ToolShell tool.

### Differentiated worksheet
**For:** one sheet with a column per level so a mixed-attainment class each gets their own. **How it works:** pick the levels; each column uses that level's own Question Options. **Where:** Worksheet mode, every ToolShell tool with more than one level.

### Depth
**For:** going beyond generated practice: hand-written questions that find misconceptions, make students explain, and stretch the secure. **How it works:** the teacher dips in by purpose (diagnose, explain, extend) and level, in whatever order the class needs. Each item is a question slide then an answer slide, with cartoon speakers, lettered options that name the misconception behind each wrong choice, and Feathers the owl giving a nudge or takeaway. A "Start here" quick check gives one question per level. Items grey out when the Question Options needed for them are off. **Where:** the tools that have a question bank (see the Matrix).

### Teach deck
**For:** the teaching part of a lesson, as slides pressed through one beat at a time before moving to practice. **How it works:** hand-written, misconception-driven slides with animated pictures (split bars, factor trees, index tiles). **Status:** Developing-tools mode only for now. **Where:** the tools with a deck (see the Matrix).

### Lessons
**For:** a teacher's sequence inside one tool: for example a Depth check, a Whiteboard practice, a Worksheet to set, then an extension. **How it works:** the burger menu's Lessons page shows a card per lesson; each step opens a pre-set mode, level and options, and a step bar keeps the place. **Status:** Developing-tools mode only for now.

### Decks (whole lessons)

**For:** teaching a whole lesson from one place, on the projector, without jumping between tool pages, and shaping it to how you teach. **How it works:** a deck is a planned run of slides (objective, vocabulary, boards to write on, targeted practice questions, Depth checks, discussions, quickfire grids, exit tickets). A board has a corner control to show it filled in, structure only or blank; the central **Skill practice** editor opens directly on the slide’s own questions. **Question brief** records the intended skill, question types, exclusions, progression, count and solution reference; it can be copied into chat. Claude supplies briefs when planning lessons, or follows the teacher’s requirements. **Add my own question** lets the teacher add directly to the set. Question, answer and worked steps are the basic fields; teaching guidance is optional. **Depth card** has its own picker. Applying the brief and questions is one undo step. The player offers previous/next questions and a clear end of sequence. **Show working** slides the question to the right while the numbered solution unfolds on the left, with previous/next steps, Show All and a final green answer marker. Authored solutions follow the matching generator’s method, labels and reveal steps. Generator slides use the same layout. Generated practice is a separate activity. Parts of a slide can appear one click at a time (a discussion shows its prompt, then the key point, then the question, then the answer). The ink pen works on every slide and clears when the slide changes. **Edit** opens the slide editor: type straight onto the slide, write maths in the equation editor (fractions and powers typed as they look), add shapes, arrows, pictures, boards, questions and Depth items, and line things up with guides. Changes are saved as you go and shared with your other devices. **Configure generator** opens a central popup with the tool’s tabs, levels, Question Options and a preview; Apply saves the setup in one undo step, while Cancel discards it. Any tool's generator can run on a slide like its Whiteboard (New question, working step by step), or fill a book activity with a printable set of questions. From a tool page, **Send to a deck** turns the current setup, or the question on screen, into a deck slide. The **Slide library** shows every layout. Open a deck from the tool's burger menu or the Decks page. **Status:** Developing-tools mode only for now; Estimation is the first deck.

### Printables
**For:** ready-made sheets with no generated questions, for the class to fill in: blank number lines, place value tables, binary tables, ratio tables and coordinate grids. **How it works:** a "Printables" heading in the burger menu lists the sheets a tool offers; one click opens the A4 page ready to print. **Where:** only tools whose working is built on a blank the student fills in (a number line, place value table, ratio table or graph); the dashboard's Printables filter lists them.

## Controls — what a teacher can change

### Levels
**For:** moving the same question type from easy to harder. **How it works:** Level 1, 2 and 3 buttons above the question. A tool can offer fewer than three; the buttons it does not use are hidden. An (i) beside the buttons (on a phone, beside the Difficulty title) says what each level means; tapping a level opens a fuller pop-up with what can be chosen there and a button to switch to it. **Where:** every ToolShell tool, and the Decision tools.

### Question Options
**For:** tuning exactly what kind of questions come up (which question types, what sort of numbers, how the answer must be shown). **How it works:** a popover of buttons grouped into pools; ticking more than one in a pool mixes them. Every option sits under one of four names, always in this order: Questions, Numbers, Method, Display. A level with more than eight choices shows them as small tabs at the top of the popover, so a few groups show at a time; a smaller one just lists its groups in that order. A label ending in an asterisk is beyond standard questioning and is off by default. Some options grey out until another option they depend on is on. Every option says in a sentence what it is for (hover its (i) on a laptop; on the Decision tools the sentence shows beside the option's heading, or under it on a phone or tablet), and the headings use one wording across the site: Title Case, one word per idea ("Method" is how it is worked, "Working Shown" is how much working, "Answer Format" is how the answer is written, "Ask for" is what the question asks for). **Where:** every tool.

### About this tool
**For:** telling the teacher in plain words what the tool is for. **How it works:** opened from the burger menu ("About this tool"); it says what the whole tool is for, then lists each sub-tool with its purpose; a sub-tool opens to show what each of its levels means and what its Question Options do (each one explained in a sentence, such as what 'Extended Range' extends; the same note appears when you hover an option's ⓘ). The level text is the same as in the level (i), which gives the quick version for the tab you are on. It does not explain the modes. It opens by itself the first time a live tool is used on a device (never from a shared link or a lesson step) and then stays out of the way; "Show tool tips again" on the landing page menu brings that back. On a phone it is a full-screen sheet. **Where:** every ToolShell, Decision and Computer Science tool, the word games, the Visualiser and the Parallel Lines Explorer (these last ones keep hand-written notes). Each ToolShell tool also has a level (i) beside the level buttons: it says what Level 1, 2 and 3 mean, and tapping a level opens a fuller pop-up with what can be chosen at that level and a button to switch to it.

### Sub-tool tabs
**For:** several related question types in one tool (for example Elimination and Substitution). **How it works:** small tabs under the title; a tool with only one sub-tool shows none. **Where:** most ToolShell tools.

### Share link (Copy Link to Setup)
**For:** sending a colleague or a class the exact setup: mode, level, options, question count. **How it works:** the address bar always holds the current setup; the burger menu copies it. A worksheet link generates the sheet on arrival. Old links never break, and when a tool's address changes the old address still opens it (Times Tables moved from `/timestables` to `/times-tables`). **Where:** every ToolShell tool.

### Recent and pinned questions
**For:** going back to a question the class has moved on from, or keeping one on hand. **How it works:** the burger menu lists the last five questions and up to five pinned ones; the pin button sits beside New Question. Memory only: gone when the page reloads. **Where:** both shells.

### Subjects and strands on the landing page
**For:** finding a tool by subject. **How it works:** three tabs, GCSE Maths, A-Level and Computer Science, each listing its strands in order of the scheme of work. Computer Science holds the revision topics ("Computer systems") and the binary and number-base generators ("Binary & number bases") together. The Classroom strand (the Visualiser) shows under every tab; internal pages sit in a Workshop strand that appears only in Developing-tools mode. **Where:** landing page.

### View as (Auto · Mobile · Tablet · Desktop)
**For:** previewing the phone or tablet layout, or fixing a device that guesses wrong. **How it works:** a landing-page menu setting, stored per device, that every shell obeys. **Where:** landing page burger menu.

### Ink pen (draw anywhere)
**For:** writing on top of any tool page, on a touch screen or interactive whiteboard. **How it works:** a pencil button opens a movable bar with Freeze, Pen, Eraser, Undo, Clear and colours. Ink stays until you change page. **Where:** every tool page, not the landing page.

### Fullscreen and the collapsible working panel
**For:** filling the screen for a whole-class view. **How it works:** Fullscreen enlarges the question; the working or visualiser panel on the right can be collapsed so a large diagram fills the width, and re-opened from a button in the question box. **Where:** Whiteboard.

### Visualiser camera
**For:** showing a student's paper or a hand-drawn working alongside the question. **How it works:** the working panel can show the live camera. **Where:** Whiteboard and the Visualiser tool.

### Working scaffold
**For:** a model for the students to copy while they work, such as a place value table. **How it works:** drawn in the working box or beside the question, with a button to hide it once students no longer need it. **Where:** the tools that have one (see the Matrix).

### Staged reveal
**For:** letting the class attempt part of the task before the answer, such as plotting a number before the answer line appears. **How it works:** an extra button in the question box (for example "Show Plot") reveals the in-between picture; Show Answer still shows everything. **Where:** Rounding.

## On the worksheet — how a sheet is built

### Calibrated worksheet (Smart Progressor)
**For:** putting a worksheet in order from easy to hard by how hard each question really is, not by which option made it. **How it works:** each question is scored from its own numbers and working; a sample of thousands cuts the scores into eight bands, and the sheet draws evenly from the bands the ticked options can reach, easy first. A **Smart Progressor** switch in Worksheet Settings turns it off. A few variety pools (the zero kinds in Rounding, Speed / Distance / Time in a mix) are also kept roughly even on a short sheet by the same switch. **Where:** every tool with the Calibrated mark on the dashboard.

### Say the prompt once
**For:** a cleaner sheet when every question starts with the same instruction ("Simplify:"). **How it works:** the shared wording is shown once above the sheet instead of in every cell. Printing still repeats it. A switch in Settings puts it back.

### Shape labels that avoid each other (and Reduced Labelling)
**For:** a shape picture where every length is easy to read and nothing sits on a line or on another label. **How it works:** each label tries a grid of spots beside its side (slid along it, pushed out, inside the shape or on the line when there is no room), scores each against the outline, the dashed helper lines, the other labels and the picture's edge, and takes the clearest; a thin dashed line joins it to its side. **Reduced Labelling** (a switch) leaves out only the labels the drawing already implies (a side equal to the one opposite it, a rectangle's other two sides), so nothing has to be worked out; it pairs with Some Missing, whose ? sides are always found by adding or taking away. **Where:** Perimeter & Area.

### Condensed wording
**For:** fitting more questions on a sheet by shortening long wording. **How it works:** a switch in Worksheet Settings shows the question with a small tag ("(3 d.p.)") instead of the full sentence. Print and the whiteboard keep the full wording.

### Answers in place of the question
**For:** checking a sheet cell by cell. **How it works:** with answers on, each cell shows its answer instead of the question; double-tap a cell to flip just that one.

### Own print layout (diagram printing)
**For:** printing sheets of pictures (angles, number lines, grids) neatly, with the right number per page. **How it works:** diagrams are packed by their shape using the same page-fill engine as text sheets; more columns means smaller, denser diagrams. **Where:** the diagram tools.

## Behind the scenes — what makes a question good

### Instant reformat
**For:** changing how a question is shown without changing the question. **How it works:** when a display option is switched (decimal or fraction, say, or words in the column headings), the shell redraws the same maths in the new form instead of making a new question, so the class keeps the problem they were looking at. Every tool gets this for any option marked as display-only. **Where:** every tool, for its display options.

### No repeats in recent questions
**For:** a class never seeing the same question twice in a row, or again within a few clicks. **How it works:** New Question compares the new question's content with the last 15 shown and quietly makes another if it matches (the Decision tools check the last 8). It compares what is on screen as well as the maths itself, not a label, so two questions that look the same are caught, and when in doubt it asks for another question rather than letting a repeat through. Replaying a recent or pinned question, and share links, still show exactly what was saved. Worksheets use the same check across the whole sheet, so a sheet never repeats a question unless the tool cannot make enough different ones. **Where:** Whiteboard and Worked Example in every ToolShell tool, and the Decision tools.

### Changing options keeps your question
**For:** changing your mind without losing the question on screen. **How it works:** changing a Question Option no longer replaces the current question. The next question you ask for follows the new options. Only a change of level or sub-tool gives a new question straight away. **Where:** Whiteboard and Worked Example in every tool, and the Decision tools.

### Developing picture
**For:** a Worked Example where one picture is drawn up step by step beside the working (a place value table filling in, a graph being built, a diagram getting its angles). **How it works:** the picture updates in place as the steps advance instead of being reprinted each time. **Where:** the tools marked on the Matrix.

### Closing answer step
**For:** the working ending by stating the answer, so no separate answer box is needed. **How it works:** a tool whose last step already states the exact answer can switch the extra green answer box off.

### Representations (the eight pictures)
**For:** the same picture meaning the same thing wherever a student meets it. **How it works:** bar model, number line, area model, algebra tiles, negative counters, prime factor tiles, place value table and ratio table are the site's visual vocabulary; new pictures must start from one of them. The Matrix shows which tool uses which.

### Techniques engine
**For:** reusable blocks of worked-example steps (solving a linear equation, substituting back) so many tools explain the same move the same way. **Status:** built and used by a few tools; a Technique Library page shows them in Developing-tools mode.

### Skill links
**For:** a dotted-underline word in the working (for example "LCM") that would open a short slide lesson on that skill. **Status:** Developing-tools mode only: the markers are in three tools and show as plain text otherwise.

### Smoke tests
**For:** catching a broken question before a teacher meets it. **How it works:** every tool is run through 40 questions per tab and level; the tests fail on a crash, a repeated question key or any maths that will not draw. The Matrix shows which tools are covered.

### Spec
**For:** a written brief in `specs/` that says what a tool should teach, with sample questions that define "correct". The Matrix shows which tools have one.

## On the dashboard — where Harry and Claude look

### Facts
**For:** what each tool is (live or not live; its shell; what it has), read from the code so it can never be out of date. Run `npm run facts` after changing a tool.

### Tool notes
**For:** what people say about each tool: status, in development, what we want to change, how it differs from the standard, the picture used, review, open questions. Written by Harry in the dashboard or by Claude through the API.

### Future developments
**For:** ideas that are not scheduled, kept so they are not lost (from `docs/FUTURE.md`). **How it works:** the dashboard's Developments drop-down (Future developments) lists each idea with what it is, why it waits and what it pairs with; a matching planner note keeps the same list. Claude does not read it unless asked.

### Developments
**For:** the open decisions and loose ends (from `docs/TIDY_UP.md`) and, by feature, which tools differ from the standard tool.
